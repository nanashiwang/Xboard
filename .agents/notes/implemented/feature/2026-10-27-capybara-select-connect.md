# Agent Note: 点击节点即连接并同步连接按钮

Status: implemented

## Problem

用户在 Windows 切到全局后看到 ping0.cc 仍为原 IP，随后确认点击一键连接即正常；本次反馈由未开启连接造成，不能据此认定 Windows 代理或节点故障。用户要求右侧点击节点就连接，已连接时直接切换，主按钮同步实际状态。

## Decision

新增原生组合操作，未连接时先沿用账号/套餐同步，再在最新列表中确认并选择点击的节点，最后开启系统代理；已连接时只切换，不重复同步账号、开启代理或检测外网。节点和连接状态一起返回，前端共用即时操作锁，拒绝旧轮询覆盖操作结果。失败刷新真实状态，仍可重试当前节点。登录、自动准备、测速及仅切模式不自动连接，主按钮继续允许手动连接和断开。

## History audit

- [分流模式](../../implemented/feature/2026-10-26-capybara-routing.md)部分重叠，模式本身不连接，GLOBAL 持久化和只作用于新连接的边界保留。
- [桌面架构](../../implemented/architecture/2026-10-23-capybara-desktop.md)部分重叠，复用系统代理恢复、资格校验和 Runtime → Nodes 锁顺序。
- [Windows 诊断](../../implemented/process/2026-10-26-capybara-windows-diagnostics.md)部分重叠，本次未连接反馈已由用户验证；历史美国01故障仍无现场报告，不混为一事。
- [后台启动](../../implemented/feature/2026-10-26-capybara-background-startup.md)不改决定，自启及重开仍不自动接管系统代理。

## Alternatives considered

- 前端顺序调用选择和连接改动较少，但选择方法吞错、连接时订阅重载可能删除目标，会误连旧节点或别的节点；使用原生组合并在同步后再次验证目标。
- 点击模式也自动连接可以减少一步，但用户明确要求节点点击触发，模式选择仍有独立用途；仅主动点节点或连接按钮触发。

## Verification

前端新增8项完整App回归，覆盖点击新/当前节点、已连接切换及手动断开、失败重试和套餐失效回读、同帧操作互斥、旧快照和连通性警告。原生新增6项回归，覆盖启用失败、已连接不重复启用/探测、检测失败真实状态、重连清错、失效目标及内核缺失；测试注入代理操作，不更改本机系统代理。完整检查和发布状态见[进展](../../../../progress-log.md#2026-10-27卡皮巴拉点击节点即连接)。

## Consequences

节点点击成为明确连接动作，减少漏点主按钮的困惑，代价是组合命令需 Runtime 锁，正在进行的账号同步可能延迟确认；已连接切换不增加账号请求。系统代理开启但连通性检测失败沿用“连接待检查”，不伪称线路成功。旧浏览器连接仍可能使用旧出口，TUN 和三系统实际网络验收不在本次自动化测试覆盖范围。
