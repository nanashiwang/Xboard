# Agent Note: 官网优先分发卡皮巴拉桌面客户端

Status: implemented

## Problem

卡皮巴拉已发布桌面测试版，官网的下载入口仍展示 Clash Verge Rev，并要求所有设备导入订阅，用户无法找到自有客户端或理解直接登录的流程。

## Decision

复用 /clients、现有安装包清单与 SHA-256 校验镜像脚本。Windows、macOS、Linux 默认提供已发布的卡皮巴拉 0.1.0-alpha.2；不猜测 macOS 芯片，让用户明确选择。Android/iOS 仍展示第三方方案，Clash 桌面导入移至独立兼容入口。

以 account/subscription 标识安装流程：自有客户端只提示安装、登录和连接，不请求个人订阅；第三方保留鉴权、资格检查、超时和失效清理。页面公开标注测试版、系统要求、系统代理和未签名边界。首页、下载页和下载教程同步措辞，不声称自有移动版已发布。

安装包镜像须先下载并验证已发布资产，再部署引用它们的页面；失败不得继续切换页面。知识库只更新文章 5，先核对原正文摘要并保存备份，其他文章不读取或修改；正文冲突时拒绝覆盖。保留旧安装包链接。网站沿用 GHCR 镜像版本，本次不改桌面二进制或新建桌面版本。

## Existing notes audit

- [桌面客户端](../../implemented/architecture/2026-10-23-capybara-desktop.md)部分重叠：复用已完成的发布资产和能力边界，不更改应用工程。
- [网站入口](../../implemented/architecture/2026-10-22-website-flawless-relay.md)无关：不改变域名、代理或节点拓扑。
- 检索活跃笔记未发现独立下载分发决定。

## Alternatives considered

- 让首页直接下载一个安装包步骤更少，但无法可靠区分 macOS 芯片且会误导手机访客；保留设备选择页并按系统推荐。
- 直接跳 GitHub Release 维护量少，但下载受 GitHub 网络可达性影响；复用本站静态镜像，GitHub 仅作为备用来源。
- 删除所有第三方入口能简化页面，但当前没有自有移动端且桌面仍为测试版；保留清晰区分的兼容入口。

## Verification

17 项 PHP / 153 断言、5 项首页 Node、4 项知识库更新测试、Blade 编译、JS 语法与 actionlint 通过；5 个安装包与发布元数据及本地下载摘要核对一致。真实浏览器完成所有平台切换、320–1440px 无横溢、暗色、卡皮巴拉页签不请求订阅、第三方模拟导入与退出后清理。安装包镜像、页面部署和教程同步分别在进展记录报告。

## Consequences

测试版尚无 TUN、代码签名、公证或自动更新；Linux 自动代理限 GNOME。生产镜像和静态安装包是两个发布单元，须保持上线先后顺序，镜像失败保留原页面。
