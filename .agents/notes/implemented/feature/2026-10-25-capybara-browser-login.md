# Agent Note: 卡皮巴拉复用网页登录状态授权桌面登录

Status: implemented

## Problem

用户希望点击桌面登录后打开浏览器，复用官网已经登录的账号，避免在客户端再次输入密码。此前钥匙串修复已发布 alpha.4，但用户在当前本机应用中仍遇到原生登录连接错误；公开接口、空登录校验和独立 Rust 请求可通，真实账号路径仍未通过，不能把浏览器授权当成已验证的网络故障修复。

## Decision

使用短时设备授权：客户端创建五分钟请求并仅在原生内存保留随机兑换秘密；服务端只保存秘密摘要。浏览器仅收到公开请求 ID，通过现有同源 VUE_NAIVE_ACCESS_TOKEN 验证网页登录状态，展示账号和设备，用户确认后批准。客户端持秘密轮询，在事务内一次性兑换既有 ClientAuthService 的设备令牌；浏览器不接收桌面令牌，也不把网页登录令牌放入 URL。

未登录时沿用官网登录页面，用 sessionStorage 保存只有请求 ID 与期限的返回标记；独立脚本在验证网页会话后跳回固定授权页。拒绝任意跳转地址，授权页禁止嵌入与缓存。保持设备限额、封禁检查、桌面令牌作用域、续期轮换及钥匙串保护。现有密码 API 保留给旧客户端；新桌面主登录入口文案为“账号登录”，点击使用浏览器授权，提供等待、取消、重开和明确网络失败提示。alpha.10 按反馈移除底部重复的“取消”按钮，保留右上角关闭与 Esc 调用同一取消逻辑；授权协议不变。

客户端未登录首页及登录等待页提供“注册账号”。原生沿用同一授权协议，只给固定授权页添加 `flow=register`，不接收任意跳转 URL；没有有效网页登录状态时，网页保存原请求 ID/期限后直接进入 `/#/register`。注册成功获得的官网会话由现有返回桥接验证，再回到授权页由用户确认。已有官网会话时先展示当前账号，不能静默退出或自动改用其他账号。登录等待中切换注册会替换并取消旧请求，重试与重新打开保留注册意图。验证码、邀请码、注册关闭和密码规则完全由现有官网注册实现负责；超过五分钟后注册账号仍有效，用户重新点账号登录继续授权。

授权请求过期、取消、重复兑换、错误秘密和不同网页账号重复批准均拒绝；浏览器批准不能由已有 desktop/client 作用域令牌发起。网络重试不重放已经兑换的续期令牌。未批准的轮询不生成登录令牌。

## Alternatives considered

- 直接将网页 token 放进自定义协议 URL 最省改动，但会暴露长期会话并混淆网页/桌面权限，不采用。
- 本地回环 HTTP 回调能让浏览器直接送达结果，但引入监听端口、浏览器本地网络访问权限与跨平台回调校验；本次复用服务端轮询，一次性秘密不会离开原生进程与账户服务。
- 继续只用应用内密码登录无需服务端更新，但不能复用用户现有网页登录状态，不符合本次要求。
- 在原生客户端另做注册表单可少一次网页跳转，但要重复维护验证码、邀请码、条款及注册策略；复用官网注册与既有授权返回更一致，不新增独立注册 API。

## Consequences

生产验收以实际接口与运行镜像为准：客户端 alpha.7 已发布时，生产仍运行 `8ecbd73`，`POST /api/v1/auth/browser/start` 返回 404。修复复用已有服务端实现和 Production Deploy，指定完整镜像 revision，更新前使用 SQLite 在线 backup API 创建 0600 快照并做完整性检查；普通文件复制无法保证 WAL 数据完整，因此不采用。备份失败必须阻止迁移与重启。上线后检查授权页面、主题返回脚本及 start/context/poll/cancel；完整账号批准与原生恢复另行实测，发布安装包不代替服务端上线。

新增表随 e278451 生产部署完成迁移，主备域发起/等待/取消接口与网页返回脚本已验证；用户已完成真实官网批准，本机 alpha.7 登录成功；正常退出重开自动恢复账号与流量，未弹钥匙串密码框。网站现有 Xboard 主题加载固定返回脚本，其他自定义主题需集成后才能自动返回。网络中断丢失一次性兑换响应可能留下已发放但客户端未获得的会话，依现有到期/设备解绑清理；不为重试把秘密或令牌放入浏览器。上线服务端前新客户端无法完成授权。原生账户网络故障仍可能影响发起/轮询/同步，需按错误类别继续排查。授权页需要一次明确确认，防止用户无意批准从其他地方复制来的请求。浏览器与客户端使用同一固定站点，不跨域复制账号状态。
