# Agent Note: 按人民币标价收款且不向客户加收支付成本

Status: implemented

## Problem

用户要求“显示多少就是多少”。面板手续费虽然为零，生产 Stripe 美元售价仍含 4.4% + $0.30 成本预算，造成标价与实际付款不一致。

## Decision

复用已存在的 CNY Checkout 分支，保持站点人民币记账，通道改为人民币收款，同时将美元成本预算置零、固定及比例手续费保持零。当前商户与支付方式配置已实测接受 CNY、金额为原始人民币分，配置已应用并回读。Stripe 对商户的费用由商户承担，用户发卡行独立费用不在本站控制范围。

通过[运维脚本](../../../../.docker/production/checkout-no-surcharge.php)先备份通道配置；识别并过期本项目当前未付款的旧 USD Checkout 链接，保留已支付报价和历史回调验证。其他项目会话、订单、价格与账户级设置不改。历史 USD 商品清单不再作为当前配置导入依据。

## Alternatives considered

- 仅将 USD 成本预算改为零，保留固定汇率换算：修改更少，但用户仍会看到人民币标价与美元支付金额，银行换算也可能产生差异，不能严格满足同币种同金额。
- 复用现有 CNY 分支：能直接传递人民币应付分，无需改代码、重建应用；前提是当前商户配置实测接受 CNY。若不接受，保留现状并记录具体阻碍，不冒称已实现同金额付款。

## Verification

- 2026-11-13 11:59（北京时间）配置生效；本地隔离 PHP 8.2.33 容器 Payments 21 项/95 断言通过。切换前 API 探测及切换后实际运行 PaymentService 均创建 cny/990 收银台，包含微信和银行卡，随后立即过期，不付款。
- 线上通道回读 cny、两层手续费均为零；实际运行插件生成 990/3200 的同币种同金额请求，禁用自动换汇。
- 切换前后本项目旧未付款 USD 链接均为 0，无需过期客户会话；历史已支付报价保留。通道完整快照存于服务器 storage/app/backups/checkout-no-surcharge-20261113/，目录 0700、文件 0600。
- 同步 README、能力地图、支付文档及进展记录，完成门禁与精确提交回读。

## Consequences

CNY 收款可能增加商户结算费用；不通过客户加价抵消。旧收银台需重新打开订单付款；切换期间正在完成的付款仍按原报价校验，不能改写已支付历史。真实付款与到账不在自动验收范围。
