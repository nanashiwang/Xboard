# Agent Note: 登录即加载节点与独立延迟测试

Status: implemented

## Problem

用户要求登录后自动展示套餐节点、点击节点及时切换、一键查看各节点延迟。现有首页仅连接后显示节点，切换还同步等待外网检测及账号刷新，造成迟缓。

## Decision

有效账号同步后下载并校验本人 Mihomo 配置，在回环地址启动内核准备节点；系统代理仅由连接按钮开启。断开保留内核和节点选择，退出、注销、资格失效及安装更新停止内核并恢复代理。节点状态独立于账号网络锁，选择只等待本地内核确认；前端立即显示待确认状态，失败保留原选择。节点状态带递增版本，阻止旧轮询覆盖操作结果。

一键测速通过内核逐节点 HTTP 延迟 API，固定检测地址、最多四路并发、单项五秒超时；去重节点并逐个返回毫秒或不可达。配置重载/注销取消旧轮次，结果仅属于当前配置，不改变系统代理或选中节点。

## Alternatives considered

- 只从 YAML 解析名称可免启动内核，但无法在连接前验证选择组与完成真实节点测速；复用内核回环 API，使预选和测速使用同一份配置。
- 只优化界面高亮改动少，但外网检测和账号锁仍阻塞真实切换；拆分节点状态，并保留内核确认与失败提示。

## Validation

本地合并工作区前端 38 项、网页/发布脚本 12 项、Rust 19 项通过（既有钥匙串手动测试 1 项跳过）。真实 Mihomo 内核执行回环 HTTP 204 延迟检测、拒绝非法节点和未授权控制器，验证无系统代理恢复日志；四并发、增量结果和注销后旧结果丢弃有回归。CUA 模拟验证连接前选节点/测速、连接和断开保留选择、超时显示、明暗主题及 760px 无横向溢出。Mac 合并包构建与签名检查通过；真实账号节点与发布待验，证据持续记录到 progress-log。

## Consequences

后台内核增加少量资源使用；延迟受当前本地网络和检测站点影响，不代表带宽。已有第三方系统代理不被自动接管。内核进程异常仍由看护进程恢复代理。
