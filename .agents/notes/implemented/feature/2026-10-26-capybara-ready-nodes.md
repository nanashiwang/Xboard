# Agent Note: 登录即加载节点与独立延迟测试

Status: implemented

## Problem

用户要求登录后自动展示套餐节点、点击节点及时切换、一键查看各节点延迟。现有首页仅连接后显示节点，切换还同步等待外网检测及账号刷新，造成迟缓。

## Decision

有效账号同步后下载并校验本人 Mihomo 配置，在回环地址启动内核准备节点；系统代理仅由连接按钮开启。断开保留内核和节点选择，退出、注销、资格失效及安装更新停止内核并恢复代理。节点状态独立于账号网络锁，选择只等待本地内核确认；前端立即显示待确认状态，失败保留原选择。节点状态带递增版本，阻止旧轮询覆盖操作结果。

一键测速通过内核逐节点 HTTP 延迟 API，固定检测地址、最多四路并发、单项五秒超时；去重节点并逐个返回毫秒或不可达。配置重载/注销取消旧轮次，结果仅属于当前配置，不改变系统代理或选中节点。

订阅配置更新与30秒账号额度同步分开。首页提供明确的“更新订阅”入口，主动点击绕过自动周期，重新下载、校验并应用本人配置；成功时间只在内核确认应用后推进，不能用账号同步时间代替。帮助设置提供30分钟、1/3/6/12/24小时周期，默认1小时，在本机私有文件持久化。原生后台轮询根据成功应用的实际时间判断到期，应用重启重新加载，休眠后补一次到期更新；不增加依赖窗口是否可见的前端定时器。

普通下载或应用失败保留上一份有效配置和成功时间，手动操作明确返回失败；账号失效、封禁或套餐不可用继续停止连接。复用现有配置净化、摘要校验、内核热加载和回滚，保留有效节点选择及本地规则，不自动开启系统代理。配置更新成功只表示拿到并应用Xboard当前配置，不代表线路测速通过，更不会改写服务器外接节点的公钥或地址。

## Alternatives considered

- 只从 YAML 解析名称可免启动内核，但无法在连接前验证选择组与完成真实节点测速；复用内核回环 API，使预选和测速使用同一份配置。
- 只优化界面高亮改动少，但外网检测和账号锁仍阻塞真实切换；拆分节点状态，并保留内核确认与失败提示。
- 复用“立即同步流量”只需改文案，但该操作仍受配置周期限制且配置错误不会使账号同步失败，容易把旧配置显示为已更新；为订阅更新保留独立原生命令、结果和成功时间。
- 前端每小时定时便于实现界面，但关闭隐藏、重挂和休眠会影响周期；延续原生后台调度，只把周期与状态开放给界面。
