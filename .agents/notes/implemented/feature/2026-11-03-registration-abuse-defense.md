# Agent Note: 注册滥用分层防护

Status: implemented

## Problem

2026-11-03 用户反馈近期批量注册。本轮只读检查生产后台、SQLite、邮件及 Nginx 日志；完整证据与限制见[进展](../../../../progress-log.md#2026-11-03批量注册排查)。63 个同后缀账号集中出现，现有邮箱验证不足以区分自动收码与正常注册。禁止据此推断身份、认定该邮箱域所有用户恶意，或把当前配置当成所有历史时刻的配置。

## Decision

用户在诊断后明确要求“这些都弄上吧”，实施分层规则。复用现有注册入口、IP开关、配置API、Redis、日志及Production Deploy；不改变已有63个账号及付费权益。

- 发码、注册请求、成功注册名额和验证码尝试分别计数；IP/邮箱桶独立，滑动窗口由分布式锁保护，成功前预占，正确验证码先消费后写库。初始额度及回退见[运维说明](../../../../scripts/security/README.md)。失败创建保留预占；不通过自动释放造成并发额度穿透。
- 定点限制 `fldubai.com` 新注册/新用户发码，精确邮箱例外可撤销；已有用户登录/恢复继续可用。保留邮箱验证、无试用现态，不启用全域邮箱白名单。
- Turnstile 的现存widget原来仅允许board旧域；本轮控制台已补齐taige及Go，三域托管模式、无预清除、密钥不变。服务端严格hostname/action、短超时与单次token；前端错误/过期清空待处理动作，用户明确重试才重新验证。不能仅凭域缺失或组件自动reset推断10月21日历史循环的唯一原因。
- 来源链只在taige跳板和board源站vhost增加CF官方网段信任。所有交给应用的身份头由可信连接重新设置；Go保留原精确信任。生产变更使用SHA前置条件、私有备份与nginx校验恢复；尚待上线实测的结果分开记录。
- 审计保留7天，只存请求ID/结果/原因/域/带密钥摘要/成功账号ID。单域8个成功注册/小时写一次告警，不自动封禁常用邮箱。配置快照7天后每天提示人工复核；不发送外部通知，不删除账号。

本地真实Redis多进程及业务回归通过，生产发布/完整真人验收状态以[进展](../../../../progress-log.md#2026-11-03注册防护实施)为准。规则依据 [Cloudflare 服务端校验](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/) 与 [OWASP 防自动化](https://cheatsheetseries.owasp.org/cheatsheets/Bot_Management_and_Anti-Automation_Cheat_Sheet.html)。参数是可调整初始值，不能保证杜绝代理池/自动解题。

- 搜索 proposed/implemented/rejected 未发现已有注册防滥用方案归属；其余首页、通知和节点笔记不属于本决定，不修改。

## Alternatives considered

- 只打开 IP 限制：最快且已有实现，但分散来源、低速注册和代理身份混淆均削弱效果，只作为一层。
- 立即启用 Turnstile 或全站 CF 挑战：能提高自动化成本，但此前有正常用户循环失败，且 Go 当前不经过 CF 代理；应先验证组件流程，不影响机器接口。
- 只允许 QQ/Gmail 等少数邮箱：可快速挡住本次后缀，但误伤企业邮箱且攻击者可换到常见邮箱，优先定点策略与行为限制。
- 批量删除同域账号：清理直观但会丢证据，不能阻止再注册，也无法由域名独立证明每个账号恶意；暂不执行。

## Validation boundaries

- 生产变更前核实可信 IP 链，覆盖伪造转发头、CF/跳板、IPv4/IPv6 和旧域路径。
- 自动化回归覆盖并发阈值、换邮箱发码、验证码过期/错误/重放、正常注册与已有账号找回密码，计数拒绝不创建账号或额外发信。
- 浏览器验证正常用户完整注册、慢网/失败重试、桌面注册返回；Turnstile 成功/过期/重复 token 分开覆盖。
- 提供具体配置 diff、回退值及脱敏命中统计；上线后观察正常转化与误拦截，不能以 HTTP 200 或单次验证码通过代替业务验收。

## Consequences

共享出口可能误限正常用户，域名策略可能误伤企业/小众邮箱，攻击者可换域或更换 IP。审计数据需要最小化和短期留存。当前只读证据不能确定操作者身份、代理服务、收件箱控制方式或最终用途；禁止用推测代替调查结论。
