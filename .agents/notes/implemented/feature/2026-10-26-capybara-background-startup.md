# Agent Note: 卡皮巴拉自启与关闭窗口后台运行

Status: implemented

## Problem

用户要求开机自启功能，关闭窗口后继续后台运行。目前 CloseRequested 直接触发应用退出和代理恢复，没有托盘入口或系统自启设置。

## Decision

复用 Tauri 官方 autostart 插件与 tray-icon，帮助与设置提供开关，首次默认不注册；自启指当前用户登录系统后启动，以固定参数进入后台，不自动连接代理。开关状态读取系统注册结果，失败不能显示成成功，不保存第二份布尔配置。

窗口关闭只隐藏，不停止代理、账号同步或更新检查。托盘菜单提供打开与退出；手动再次打开程序、macOS Dock 重开均显示并聚焦同一窗口。明确退出沿用现有更新保护、代理恢复和核心停止流程；托盘创建失败时显示窗口并保留原退出行为，不能把应用藏到无法恢复的位置。

- 未发现同功能的活跃提案或被否方案；香港入口未提交记录与本任务无关。

## Alternatives considered

- 各平台自行写 LaunchAgent、注册表和 desktop 文件更灵活，但重复维护路径转义与平台差异；使用官方插件，仅通过受限原生命令控制。
- 关闭时退出可立即释放资源，但不符合持续代理需求；保留托盘明确退出和 Cmd+Q，而非把所有退出请求都吞掉。
- 默认开启并自动连接更省点击，但增加未经用户选择的登录启动项及网络接管；提供显式自启开关，启动后仍由用户连接。

## Testing

隔离前端 35、网页/发布脚本 12、Rust 17 项及类型/Vite、格式检查、macOS App 构建/签名通过。UI 覆盖系统状态回读、切换失败、并发保护、焦点刷新、明暗和窄窗口。macOS 实际验证自启启停、注册项路径/参数、launchctl 启动与同 PID 重开、关闭保留进程、Cmd+Q 退出。测试后恢复默认关闭并清理测试 job；未注销或重启系统。

## Consequences

关闭窗口后连接、账号同步和更新检查继续，用户从托盘或系统菜单明确退出。官方插件维护三平台注册差异，开关不另存布尔配置；系统策略仍可能禁用登录项，Linux 桌面也可能缺少托盘支持。自启不绕过系统登录或解锁钥匙串，临时签名升级仍可能需要重新授权。

用户授权与节点优化合并发布 0.1.1；统一版节点任务接管真实连接、关闭保留代理、退出清理及 Release/官网分发验收。CUA 系统菜单栏读取超时，托盘菜单点击未单独完成；Windows/Linux 真实桌面自启与实际注销/重启验证另行说明，不把构建通过当作全平台实测。证据见[进展](../../../../progress-log.md#2026-10-26卡皮巴拉开机自启与后台运行)。
