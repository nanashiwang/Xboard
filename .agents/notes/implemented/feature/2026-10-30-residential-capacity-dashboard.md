# Agent Note: 家宽订阅与出口容量看板

Status: implemented

## Problem

管理员需要按家宽节点查看订阅人数，以判断补充套餐或出口容量；在线连接数不能代表订阅人数，历史分配和续费预留也不能重复累计。

## Decision

用户随后要求移至左侧独立模块，展示选择由[家宽独立页](../simplification/2026-10-30-residential-capacity-page.md)局部替代；下述初始首页方案保留背景，统计口径和权限继续有效。

管理首页增加本仓库维护的只读卡片，沿用既有管理扩展方式，不改编译前端。管理员API按dedicated套餐统计未封禁且未到期（含永久）用户；流量耗尽仍保留有效订阅和名额。复用DedicatedExitService::occupied的有效用户/订单预留口径，每个分配只计一次，拆出已分配订阅与仅预留；展示每个出口的IP、健康、容量、占用、可新增名额。可新增受每出口5名、健康时效、备用状态、套餐上限和销售状态共同限制。保留有占用的停用出口以显露异常，无占用的退役出口不干扰当前列表。API不返回用户身份和代理凭据、不清理分配、不运行健康探针。

共享节点按名称中的“家宽”标记发现当前公开且没有独享专属标记的节点，按实际后端合并别名、合并权限组，只保留至少授权一个普通套餐的后端，对未封禁未到期且持有普通套餐的用户去重。共享后端可能同时有启用或退役的固定池记录，这些历史/复用记录不取消普通套餐权限；仅监控组可见的源节点不算共享套餐。同一用户可计入多个共享节点，各行不相加；流量耗尽仍有订阅，不代表当前可连接或并发人数。独立控制器避免旧统计控制器初始化Redis依赖；数据仅来自数据库。前端每60秒刷新，路由离开或认证变化即清除，失败不保留旧容量冒充现态。

## Alternatives considered

- 用在线人数或订单数替代：会漏掉离线订阅、重复计算续费，不适合容量规划。
- 在统计请求中调用分配/清理：可能改变真实容量，拒绝；只读查询复用既有占用条件。
- 编辑编译后的React包：不具备稳定维护入口，采用已有独立扩展模式并验证路由/登录/窄屏。

## Testing

PHP相关94项571断言与新增前端5项回归通过，覆盖管理员权限、永久/过期/封禁/耗尽、续费去重、预留过期与处理中订单、健康过期/备用/停用、销售上限、共享别名去重和空数据。Playwright使用合成数据验证桌面、390px窄屏、深色模式、刷新失败与重试、路由往返和退出登录；夹具人数不作为生产人数。构建和生产验证见进展记录。

## Consequences

首次生产验收发现共享为空：两个普通节点保留退役固定池记录，不能据此排除整个后端。已按实际公开权限修正，并补充当前/退役池复用、独享别名和仅监控来源回归；修正后相关PHP 95项576断言、前端5项通过，不修改节点配置。构建和生产验证见进展记录。

获得实时名额和订阅占用证据，不代表并发性能或带宽容量；页面刷新时重新查询，不采集个人信息。独立扩展依赖固定管理端DOM结构，升级上游前端需复验挂载。
