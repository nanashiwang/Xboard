# Agent Note: 卡皮巴拉每六小时检查与确认更新

Status: implemented

## Problem

用户希望客户端自动发现新版本，每六小时检查一次，并由用户决定是否更新。现有客户端只有发布页链接，订阅状态轮询不能承担应用版本更新。

## Decision

原生进程独立调度更新，检查时间持久化；首次启动检查，重启不重置六小时周期，休眠恢复补查，帮助页可手动检查。发现新版显示版本与说明，用户确认前不下载或安装；稍后关闭本轮提示，下个检查周期可再次提醒。

0.1.0 起，已发现新版后帮助页保留“查看更新”，重新打开同一确认弹窗，不再次发起网络检查或直接下载。版本含预发布后缀时才发布 GitHub prerelease；正式语义版本发布为正式 Release，应用显示“正式版”。所有目标成功并验签后才允许更新官网索引，GitHub Release 和生产分发分别核验。

复用 Tauri 官方 updater 的签名验证和安装能力，更新公钥随应用发布，私钥只保存在本机受限目录与 GitHub Secrets。发布流程产生四个目标的签名更新附件及静态索引，完整发布后才更新分发入口。下载与校验完成后恢复系统代理，再安装重启；恢复失败停止安装。Linux DEB 检查和提醒共用，确认后进入官网下载页由系统安装器更新，不声称可自替换 DEB。

## Alternatives considered

- 只定时打开发布页最简单，且可复用现有分发，但每次都要求用户寻找安装包，无法实现已确认后的连贯升级；仅在 DEB 的系统包管理边界保留该方式。
- 启动时无条件检查容易理解，但频繁重启会打破六小时周期；采用持久化时间戳与手动检查例外。
- 自动静默安装省去操作，但用户明确要求确认，且代理需恢复后才可退出，不采用。

## Testing

本地 11 项前端、8 项 Rust、2 项发布签名校验测试通过；覆盖首次启动、六小时边界、重启、休眠、时间回拨、手动检查、失败周期和检查互斥，以及稍后不下载、确认才安装、错误重试、登录不被打断、DEB 提示和更新中关闭保护。签名校验覆盖包体、可信注释篡改与错误密钥；本地实际 macOS 更新包通过同一验证器。生产构建、actionlint、深浅主题与 760×620 弹窗浏览器验收通过。四目标 CI、发布附件与分发上线证据分别记录于 progress-log，不以本地检查代替。

分发同步的 4 项回归覆盖全量成功、重复执行、包体损坏、索引签名不一致和索引顺序错误；失败保留原索引。教程同步 4 项、网站 PHP 17 项 / 153 断言和前端路由 5 项通过。清单中的 `kind: update` 只标识不进入网页安装选项的附件，包体仍与普通安装包一样逐一校验。

## Consequences

更新签名不等于 Windows 发行者签名或 macOS 公证。旧 alpha.2 没有更新代码，需手动安装首个支持该机制的版本。跨平台真实安装升级仍需各系统实测。临时签名应用的钥匙串访问身份可能随构建变化；[授权交互决定](../bug-fix/2026-10-25-capybara-keychain-prompts.md)限定启动与后台不请求密码，并不替代 Developer ID 签名。

签名密钥随仓库 Secret 和受限本机目录保存，公钥进入配置；私钥丢失将中断已安装版本的更新信任链。GitHub Release 不会自动改变网站更新索引；分发必须先验证全部版本化附件，再原子替换最后一个索引文件。失败的检查也占据本轮六小时窗口，用户可手动重试。应用退出时不检查，恢复运行后补查，定时器最多有一分钟调度偏差。[后台运行](./2026-10-26-capybara-background-startup.md)仅隐藏窗口，更新检查继续；明确退出与安装前代理恢复边界不变。
