# Agent Note: 节点入口延迟、联网检测与订阅复核

Status: implemented

## Problem

同一台 Mac 上，旧客户端首项节点结果约 1.93 秒、整批约 10.05 秒。六条实际线路共用一个入口，旧版还为策略组排队。重复更新未变化的订阅也会触发内核重载。[原始实测](../../../../progress-log.md#desktop-latency-subscription-20261122)

## Decision

入口按 TCP 地址和端口合并，联网检测按订阅节点独立进行，两个结果分别显示。各自最多六路并发。账号和套餐照常复核，使用已应用配置的摘要请求条件更新，内容相同且本地内核仍有效时保留当前状态。

## History audit

[节点准备与测速](../../implemented/feature/2026-10-26-capybara-ready-nodes.md)中的真实联网验证、成功时间及代际隔离继续使用，本决定更新测速范围和相同配置的处理方式。

## Alternatives considered

单独显示入口延迟无法判定后段可用性。只提高原有并发仍会重复测试策略组。只用本地时间或摘要跳过服务端请求会漏掉资格变化。

## Validation

覆盖实际线路与策略组筛选、共享入口、局部结果、配置失效、条件请求及错误摘要。发布和分发记录见项目进展。

## Consequences

不同节点可共享同一个入口结果。虚拟 DNS 地址不能提供可靠的入口计时。联网结果仍受出口、检测站点及五秒截止时间影响。
