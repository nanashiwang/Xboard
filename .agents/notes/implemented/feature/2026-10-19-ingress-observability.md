# Agent Note: 两段线路的入口与隧道观测

Status: implemented

## Problem

完整代理检测无法区分多个节点共同经过的第一段与各自出口。用户要求在节点质量页观察第一段服务器，以便定位共同瓶颈。

## Decision

在完整页面内增加入口分层观测：NAS 每轮对显式绑定的入口执行一次直连 HTTPS 健康检查，验证证书、HTTP 和固定响应；独立只读采集器复用 machine 上报，记录 CPU、内存、物理网卡收发及 WireGuard peer 的握手时间和三次 ICMP 探测。节点与隧道地址显式绑定，不用 parent_id 推断实际路径。入口采样独立于完整代理统计，不改变任何业务路由或测速预算。

管理员 CLI 配置入口与节点映射，生成权限为 600 的采集器配置；探针只能上报自身范围中绑定的入口。入口明细保存 24 小时，重复或旧上报不覆盖新结果，失联/接口错误不得继续显示正常。网页同时展示资源、第一段探测及逐节点隧道结果，保留未知状态，避免自动断言慢速根因。

- Clash DNS、项目流程以及既有未提交香港迁移记录不属本次决定。

## Alternatives considered

- 只展示 CPU 和心跳接入最快，但不能分辨用户到入口或入口到出口的网络问题，故补充两侧小流量检查。
- 在入口再运行完整吞吐测速可以比较两段容量，但会增加共享链路负载和费用；当前先提供资源与连通性证据，容量测试另行控制预算。
- 从公开节点 parent_id 推断入口绑定无需配置，但该字段只表示后端继承，不证明真实网络路径，因此采用显式拓扑映射。

## Verification

PHP 18 项、106 断言及带真实内核的 Python 12 项回归通过，覆盖入口上报范围、旧数据/重复幂等、固定响应、代理环境、失联和缺测。真实后台壳验证分层卡片、逐节点隧道、页面内入口历史、过期状态和主题。正式部署后 NAS 1.1.0 与入口只读服务持续上报，历史已包含真实超时及对应机器资源；13 个 peer 显式匹配真实 Nginx 路径。构建、生产采集和浏览器验收的详细证据见 [progress-log](../../../../progress-log.md#2026-10-19第一段入口分层监控)。

## Consequences

ICMP 可能被防火墙限制；HTTP 小请求和网卡当前流量不能证明带宽容量。握手与探测必须结合时间和完整请求结果判断，不能因为入口健康就宣称出口必然故障。
