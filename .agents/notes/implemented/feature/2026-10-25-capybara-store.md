# Agent Note: 卡皮巴拉客户端套餐购买

Status: implemented

## Problem

用户要求把侧栏“我的账户”改为“套餐”，直接选择并购买套餐。现有页面仅展示账户状态并跳转网站，Desktop 凭据不能调用网站用户接口。

## Decision

客户端增加公开套餐目录、登录后选周期和下单、待支付订单恢复、支付方式与费用确认、支付结果轮询。浏览器打开支付平台，二维码在客户端显示；只有服务器订单已完成才报告开通。左下角保留账户入口。

Desktop 新增限定的商店接口，沿用 client.auth/client.device 和网站 PlanService、OrderService、OrderController 支付/取消，金额、折扣和余额均由服务器计算。原生桥保管令牌；支付链接只来源于服务器响应，限制协议，禁止执行返回 HTML。写请求不因网络故障自动重试。

## 0.1.22 套餐目录加载

旧版在切页时卸载套餐组件，每次打开都要重新等商店接口。现在收到账号状态后通过公开目录或本人商店接口预取，离开页面保留当前会话的列表与所选周期并暂停订单轮询。返回时直接显示已有内容，超过一分钟的目录在后台更新。失败时在页面可见期间每 15 秒重试。换号清空订单、余额、二维码、支付方式与优惠码，丢弃迟到回包。订单操作优先于较早发出的目录读取。

只在内存保留当前会话结果可避免将个人可见套餐与订单写入跨账号缓存。服务端继续逐单核定金额、可售资格和库存。[导航、慢响应与换号回归](../../../../progress-log.md#desktop-release-022)。

## 0.1.23 桌面钱包

网页个人中心与桌面商店均读取同一用户的 balance。桌面钱包先显示当前会话已取得的余额，进入页面、重新聚焦或在前台每 30 秒向本人商店读取更新。钱包按需返回最近 10 笔用过余额的套餐订单，取消状态标记已退回。继续使用原有订单结算与取消流程，避免维护第二份余额或在客户端重复扣款。网页入口沿用当前可信域的 /#/profile。金额均由服务端以分为单位返回，测试记录见[进展](../../../../progress-log.md#desktop-release-023)。

## Alternatives considered

- 只把入口改名并跳转网站：改动最小，但不能在此选套餐和确认订单。
- 嵌入整个网站：可复用页面，但依赖浏览器会话、远端脚本与 WebView 支付兼容，扩大凭据边界；采用本地界面加限定接口。

## Validation

Desktop API 56 项 / 512 断言、前端 23 项、Rust 15 项及构建通过，明暗主题/760px/二维码浏览器模拟验收通过。发布、生产部署与真实付款见[进展](../../../../progress-log.md#2026-10-25卡皮巴拉客户端套餐购买)。

- 未登录能浏览真实套餐，登录后保留选择并购买；无价格、售罄、失败状态均明确。
- 服务器拒绝跨用户、未绑定设备、停用账户及不可购套餐；重复提交不会创建第二张待支付订单。
- 金额显示含余额/折扣/手续费，零元订单、二维码、浏览器支付、继续支付/取消及完成同步有回归覆盖。
- 前端/Rust/后端检查与明暗窄屏验收通过，三平台发布完整；生产部署和真实付款单列。

## Consequences

新接口需要部署服务器；未部署显示服务不可用，不能拿模拟目录冒充真实套餐。支付异步开通需要现有队列，浏览器返回不等于付款成功。

登录状态变化清理购买忙碌状态，旧会话迟到订单不进入新会话；该边界有专门前端回归覆盖。
