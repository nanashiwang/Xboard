# Agent Note: 卡皮巴拉客户端套餐购买

Status: implemented

## Problem

用户要求把侧栏“我的账户”改为“套餐”，直接选择并购买套餐。现有页面仅展示账户状态并跳转网站，Desktop 凭据不能调用网站用户接口。

## Decision

客户端增加公开套餐目录、登录后选周期和下单、待支付订单恢复、支付方式与费用确认、支付结果轮询。浏览器打开支付平台，二维码在客户端显示；只有服务器订单已完成才报告开通。左下角保留账户入口。

Desktop 新增限定的商店接口，沿用 client.auth/client.device 和网站 PlanService、OrderService、OrderController 支付/取消，金额、折扣和余额均由服务器计算。原生桥保管令牌；支付链接只来源于服务器响应，限制协议，禁止执行返回 HTML。写请求不因网络故障自动重试。

## History audit

- [桌面架构](../../implemented/architecture/2026-10-23-capybara-desktop.md)：部分重叠，本篇扩展其原有浏览器套餐管理边界。
- [浏览器登录](../../implemented/feature/2026-10-25-capybara-browser-login.md)：部分重叠，复用登录与设备凭据；不改授权协议。
- 下载与钥匙串笔记：无关，保留原决定。

## Alternatives considered

- 只把入口改名并跳转网站：改动最小，但不能在此选套餐和确认订单。
- 嵌入整个网站：可复用页面，但依赖浏览器会话、远端脚本与 WebView 支付兼容，扩大凭据边界；采用本地界面加限定接口。

## Validation

Desktop API 56 项 / 512 断言、前端 22 项、Rust 15 项及构建通过，明暗主题/760px/二维码浏览器模拟验收通过。发布、生产部署与真实付款见[进展](../../../../progress-log.md#2026-10-25卡皮巴拉客户端套餐购买)。

- 未登录能浏览真实套餐，登录后保留选择并购买；无价格、售罄、失败状态均明确。
- 服务器拒绝跨用户、未绑定设备、停用账户及不可购套餐；重复提交不会创建第二张待支付订单。
- 金额显示含余额/折扣/手续费，零元订单、二维码、浏览器支付、继续支付/取消及完成同步有回归覆盖。
- 前端/Rust/后端检查与明暗窄屏验收通过，三平台发布完整；生产部署和真实付款单列。

## Consequences

新接口需要部署服务器；未部署显示服务不可用，不能拿模拟目录冒充真实套餐。支付异步开通需要现有队列，浏览器返回不等于付款成功。
