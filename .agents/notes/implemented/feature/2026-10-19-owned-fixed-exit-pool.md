# Agent Note: 自建线路接入固定出口池

Status: implemented

## Problem

用户确认将现有自建线路接入出口池，保留每账号固定出口、每出口最多五个账号。旧专属实现依赖 SOCKS 出口，现有线路则通过入口和 WireGuard 到自建 VLESS 后端；直接标记原节点为专属会排除普通用户。线上专属权限组目前没有节点，历史人工订单仍等待出口。

## Decision

复用自建后端和现有严格 TLS 代理监控。固定出口单独引用共享后端和指定探针，不改变原公共节点的专属标记；为专属组创建复用同一路径的订阅记录，后端同时保留普通组用户并只授权对应出口的专属账号。只依据新鲜、匹配实际出口 IP 的代理检测恢复健康，保留现有故障阈值和五名额分配事务。生产清单选择 12 条美国主线路和 1 个去重后的 CF 美国出口；香港作为独立公共备用。

价格、总销售上限和上架状态保留；不因接入新出口自动扩大销售。订单依照原调度在健康恢复后开通。不得把普通共享服务器描述成物理独占或经过核实的住宅 IP。

## Existing decision audit

[专属订单等待](../../implemented/bug-fix/2026-10-19-dedicated-admin-order-failures.md)部分重叠，保留预留与重试契约。[第一阶段迁移](../../implemented/architecture/2026-10-17-stage1-replacement.md)部分重叠，复用原节点、入口和后端隔离。[节点质量探针](../../implemented/feature/2026-10-18-node-quality-probes.md)部分重叠，复用真实出口检测。既有未提交香港入口笔记保持原归属。

## Alternatives considered

- 把套餐改成共享全部线路最省配置，但用户明确选择保留固定分配。
- 直接把原后端标记 dedicated_exit_id 可复用旧代码，但会阻断普通用户和现有探针。
- 新增端口及整套节点服务可以完全隔离，但增加防火墙和入口配置变化；本次复用已经验证的链路，在用户下发时保留原权限并限制专属账号。

## Testing

只读生产检查确认旧五出口均停用、无分配，指定监控尚未设置预期出口 IP。接入清单为已有线路设置对应预期值，拒绝覆盖不一致的旧值。PHP 8.2 下相关 84 项测试、460 个断言通过，包括 11 项共享后端回归；干净 CI 发现备份目录未创建，现由命令创建私有目录并有专项回归；修正版构建和线上接入仍待执行。

验收要求：生产清单不输出用户或代理凭据；普通订阅和用户下发不变；专属账号仅收到固定出口并不能认证其他池中出口；同一出口最多五账号；不健康、过期、错 IP 或停用探针不能提供新容量；历史订单完成后有效期只增加一次；实际 HTTPS 出口与分配一致。保留回退快照并分别报告代码、构建及生产状态。

## Consequences

共享硬件和公网 IP 不构成物理独占。探针中断会停止固定出口分配，需同时检查探针账号有效期与额度。复用后端时必须覆盖全量用户与增量用户下发两条路径；入口和节点无需更换协议或开放新端口。
