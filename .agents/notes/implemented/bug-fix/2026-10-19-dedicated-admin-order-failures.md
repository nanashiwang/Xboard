# Agent Note: 专属订单预留、等待重试与失败任务分页

Status: implemented

## Problem

正式仪表盘的七日报错数持续增长。失败明细中的 OrderHandleJob 每分钟重复尝试同一笔零元人工订单，DedicatedExitService::activate 因专属出口不可用抛错，事务回滚后订单继续处于开通中。用户端创建订单已预留容量，后台 OrderController::assign 绕过了同一检查，允许创建无法交付的专属订单。

排查还发现失败详情只取 Horizon 的前 50 条再做本地分页，导致总数超过 50 后后续页面为空，妨碍核对历史错误。

## Decision

后台分配专属订阅时，在订单事务内复用 DedicatedExitService::reserve；无容量、出口不健康或过期时回滚订单。普通套餐及流量重置保持现有行为，续费复用原绑定。失败任务接口按 Horizon 的索引读取所需页面，以 50 条为块，单页最多 100 条，不删除历史记录。

用户选择保留现有卡住订单等待专属出口恢复。DedicatedExitUnavailableException 只表示 activate 未找到可用出口；OrderHandleJob 仅捕获该类型，在 open 事务回滚后保留开通中订单、记录原因与下次尝试时间，并缓存 300 秒重试间隔。CheckOrder 跳过等待中的开通订单，作业自身也跳过已排队的重复任务；间隔到期后继续自动开通。其他业务或程序异常继续交给队列失败机制。

持久化订单是恢复依据，缓存只控制频率；缓存丢失最多提前重试，不丢订单。付款受理成功不等于权益已开通，等待期间不提前增加余额、有效期或完成状态。待支付超时取消仍独立运行。检索活跃笔记的订单、专属、Horizon、队列，无同一决定；邮件提醒和探针笔记范围不同。

生产工作流允许显式传入完整 image_revision，默认仍为工作流提交。GitHub workflow_dispatch 只接受分支/标签引用，代码镜像发布后的文档提交会使 master 与镜像提交不同；目标参数在 SSH 前验证为 40 位小写十六进制，现有管理脚本仍在迁移/重启前核对镜像实际 revision，绝不绕过该检查。无需为一次部署新建分支、标签或重建仅有文档差异的应用镜像。

镜像构建通过 SOURCE_COMMIT 固定到触发 CI 的提交，并在拉取后核验实际 HEAD，再初始化子模块和安装依赖。首次生产验收发现 Dockerfile 另行 clone 移动的 master，镜像标签为 5d65688 而页面 Git 版本为后续文档提交 058fd4c；只核验 OCI 标签不足以保证源码一致。保留现有 clone 构建方式和本地未指定提交时的分支默认值，CI 始终提供完整提交号，避免扩大为整套 Docker 构建重写。

## Alternatives considered

- 仅取消本次零元订单能停止当前重复失败，但后台仍能再次创建无容量订单，因此还需入口预留检查。
- 忽略所有开通异常或清空失败记录能直接减少可见报错，但会掩盖程序缺陷且不能恢复权益；只把已识别的出口等待延后，保留订单状态、告警及既有历史。
- 仅给队列设置延迟重试无需额外缓存，但每分钟调度仍会创建新作业，无法控制同一订单的重复尝试；订单级短缓存同时约束调度和已排队作业，无需增加数据库迁移。
- 获取全部失败任务后分页最直观，但一次读取随失败量增长；按 Horizon 索引读取保持单页工作量有界。

## Verification

新增 5 项后台分配回归覆盖零元分配无健康出口时无订单残留、容量已满、预留成功及开通、续费保留名额、普通套餐和重置流程；4 项分页回归覆盖第 7 页、100 条跨块页面、末页/空页及单页上限。另 4 项等待回归覆盖历史未预留订单的支付受理、事务回滚、恢复及重复执行不重复发权益，调度间隔，其他 ApiException 不被吞掉，以及待支付超时不被缓存阻挡。PHP 8.2.33 下专属并发、订单/支付与分页共 55 项测试、276 个断言通过。Order Queue Checks 将这些检查纳入 CI；代码、CI、镜像和生产处理分别记录。

18 项运维测试、部署输入格式用例、actionlint、临时真实 Git 仓库的分支前进/提交锁定与非法 SHA 测试通过。最终镜像 9d6cf40 的两个架构均在构建日志确认源码 HEAD；生产运行 OCI revision 与页面版本相符。首次更新后跨过 5 分钟重试间隔，超过 10 分钟未新增失败；原订单保留、失败详情第 7 页可读，出口恢复后的真实交付仍未发生。工作流与现场时间见 progress-log。

## Consequences

预留后出口仍可能故障，开通事务必须继续保护用户和订单数据。原有每分钟检查仍用于恢复，但专属等待按 5 分钟间隔重试；出口恢复后可能需等待一个间隔加调度延迟。库存故障未恢复的历史订单不会因本补丁自动完成。用户授权的生产更新已完成；核验了订单金额、支付来源和当前权益，未取消、换套餐或清除历史失败。

后台分配增加一次带事务的预留，拒绝以前能够创建但无法交付的订单；保留管理员自定义金额和周期能力。失败详情每页最多读取两个 Horizon 块，历史仍按既有保留时间自然过期，不以清空日志作为验收。
