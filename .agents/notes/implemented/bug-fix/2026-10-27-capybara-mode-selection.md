# Agent Note: 切换分流模式保留已选节点

Status: implemented

## Problem

用户要求切换规则时保留此前选中的节点。当前规则选择器与 GLOBAL 各自保存选择，模式切换直接 reload，用户会看到旧的另一套节点；原保存失败回退只保留模式和规则，没有保存切换前各组的选择快照。

## Decision

模式切换以原生内核的实际选择为准，将首页当前规则组的真实节点带入 GLOBAL，从全局离开时将当前节点带回该规则组。直连不清空选择；其他规则组不修改。模式、规则与选择一起加载，加载首刻即使用目标节点；保存失败恢复切换前模式与全部选择。前端只传当前规则组提示，不传可信节点值。

0.1.11起[内网自动直连决定](./2026-10-27-capybara-private-network-routing.md)将界面全局编译为内核rule加私网DIRECT与MATCH,GLOBAL；公网使用所选节点，内网自动直连。界面模式和节点保留按持久化设置处理，配置确认同时核对规则数量与代理契约，不再仅凭内核mode区分规则/全局。

## Alternatives considered

- 前端切模式后再点节点较少改原生代码，但两次操作间会使用错误出口，且失败容易留下半完成状态；统一原生配置事务。
- 将所有规则组改为相同节点可省去当前组上下文，但会覆盖用户为不同用途设置的节点；只迁移当前组。

## Verification

前端75项、脚本16项、Rust57项通过（1项既有手动钥匙串测试忽略），TypeScript/Vite构建通过。真实内置Mihomo隔离测试经过Nodes事务验证规则/全局双向、两种直连往返、多分流组隔离、订阅刷新和磁盘保存失败恢复；核对实际内核模式、所有组选择及磁盘字节。自动组解析/循环、不可兼容目标与前端当前组传递另有回归。隔离内核测试不接管系统代理，四目标构建、Release与实机验证分别记在[进展](../../../../progress-log.md#2026-10-27切换分流模式保留节点)。

## Consequences

模式切换不再跳回旧节点，代价是切换前后读取控制器快照，失败回退同时持有规则组选择。当前组未显式选择或已消失时沿用首页的首个规则组；其他组不更改。GLOBAL只含真实订阅节点，不把DIRECT/REJECT当节点。规则组不含全局节点时切换明确失败，需先在全局选择兼容节点；不擅自覆盖其他组或自定义规则目标。

自动选择组仍可自行换出口，不能保证永久固定；其当前出口可解析时带入全局，返回时若仍指向同一节点则保留组策略。直连隐藏节点列表但不清空选择。既有连接可能沿用原路由，重启的规则组选择持久化仍遵循现有能力；本次不扩大为跨设备或全部规则选择的持久化。模式切换仍不自动开启系统代理。
