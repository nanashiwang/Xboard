# Agent Note: macOS 正式版跨版本恢复账号

Status: implemented

## Problem

用户反馈升级后总要重新通过浏览器登录。旧版使用临时签名，钥匙串账号名含可执行文件 SHA-256，重新构建就会查找一个新条目。

## Decision

正式 Mac 发布使用 Apple Developer ID Application 和固定的应用标识。钥匙串条目关联持久设备 UUID，后续同一签名身份的版本继续读取有效令牌。首次从旧版迁移时，后台只查本服务的旧条目属性；用户主动点击「恢复登录」时读取最近修改的候选，验证设备 UUID 后写入新条目。退出或失效时记录已退出，避免旧记录被再次导入。本地标记仅含状态。开发构建仍按构建隔离。

## Alternatives considered

固定条目名可以让不同版本找到同一条目，但临时签名会改变系统认定的程序身份。两个不同的测试程序以同一自签名证书签名后，后台跨构建读取仍被 macOS 拒绝。使用 Apple 发行身份并保留系统授权，避免通过放宽访问控制或落盘令牌来迁移。

## Consequences

旧临时签名条目首次读取可能需要一次系统授权。此前已撤销、过期或无法读取的凭据需要重新授权账号。发布时对两个不同的 Developer ID 签名可执行文件运行静默钥匙串创建、读取、轮换和删除测试，另验证最终应用签名。正式签名验收依赖发布环境的证书。详见[既有后台钥匙串交互边界](2026-10-25-capybara-keychain-prompts.md)及[发布记录](../../../../progress-log.md#desktop-session-wallet-026)。
