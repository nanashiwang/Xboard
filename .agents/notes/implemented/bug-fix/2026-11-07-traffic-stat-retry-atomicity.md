# Agent Note: 流量统计任务失败回滚

Status: implemented

## Problem

流量审计发现 StatUserJob / StatServerJob 数据库锁错误。用户统计逐人提交，后续用户失败后整批重试会再次累计前面已提交的用户；节点统计先提交日报再更新节点累计，后者失败重试也会重复日报。用户实际额度由独立 TrafficFetchJob 更新，不能将统计重复推断为重复扣额度。

## Decision

把一批用户统计作为同一数据库事务，把节点日报与节点累计作为同一事务。异常先回滚本次全部写入，再由既有队列重试。保留倍率、任务数据与历史数据，不猜测修正历史差额。

## Related decisions

活跃笔记检索中，[只读审计](../../implemented/process/2026-11-07-traffic-accounting-audit.md)部分重叠，负责证据与限界；既有节点倍率决定无关，保持经营规则。没有需要合并或拒绝的同类提案。

## Alternatives considered

- 禁用重试可以避免部分重复，但数据库锁会丢弃整批统计，保留重试并使失败回滚。
- 对上报内容做哈希去重容易误删合法的相同字节增量；没有节点序列号契约，本次不伪造端到端幂等。

## Verification

故障注入在旧代码下四项全部失败，复现已提交的部分统计。修复后 Operations 与流量耗尽邮件 21 项 / 115 断言通过：第二个用户失败时前一用户不落库；节点累计失败时日报不落库；重试后按 1×/2×/5× 各累计一次，新的同字节增量继续累加。CI、镜像和生产验证尚待执行。

## Consequences

批事务增加单次持锁时长，用户批次既有限制为 1000。事务提交成功但队列 ACK 丢失的重复投递仍无幂等保障。数据库回归不等于节点真实流量验收，修复不能解释数十 GB 实际扣量。
