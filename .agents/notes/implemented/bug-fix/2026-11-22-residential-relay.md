# Agent Note: 家宽连接复用普通订阅线路

Status: implemented

## Problem

Windows 0.1.16 家宽配置直接拨已购端点。用户在 11 月 21 日晚观察到同一端点经普通线路可以访问 Google，直拨时重置或超时。首页检测只取普通线路内核，家宽单独运行时会提示请先连接。旧版成功条件包含一次 Google 204，无法核对固定出口，也无法代表连接此后的可用性。

## Decision

原生连接从本人资产接口取端点和认证，通过现有带摘要校验的订阅接口取普通节点。候选优先使用当前选组解析出的具体节点，然后按订阅顺序尝试，总计最多三条。每个候选均由 Mihomo 的 dialer-proxy 将已购 HTTP/SOCKS5 出口绑定到一个普通节点。只导入候选节点，每条公网缺省路由都以家宽为最后一跳。只有服务端明确返回普通订阅不可用时，才按独立家宽权益尝试直连。

通过本次内核的本地代理发起 HTTPS 请求，对照资产地址验证出口 IP，并检查 Google 的 204 响应。通过后才启用系统代理。首页复检同一内核与出口，旧内核的检测回包不能覆盖新内核状态。客户端同步发现普通订阅失效会停用依赖它的中转连接。资产、到期、凭据及端点归属沿用[销售与连接决定](../feature/2026-11-18-residential-proxy-sales.md)。

## Alternatives considered

另设公网入口可以让外部客户端也受益，但单换端口或 IP 无法保证用户到美国的路径质量，还要维护入口认证和固定出口映射。通过两个客户端分别配置普通代理与家宽，也可以保留出口，但会增加配置步骤和恢复系统代理的竞争。本次复用一个内核和既有订阅授权。

## Consequences

用户可用一个按钮建立双跳，普通线路按其套餐计量。不可达的候选会增加连接等待时间。两家出口查询服务都不可用、Google 检测失败或出口不符都会阻止启用系统代理。切换连接沿用原有先停止旧内核的生命周期，候选全部失败后需要重新连接。

## Testing

固定 Mihomo 内核配合回环模拟中转，在同一条隧道中依次验证第一跳 CONNECT 目标、第二跳 HTTP/SOCKS5 认证和目的地址、最终网页请求与 204 回包。另验候选优先顺序、空订阅、独立直连、首页的线路显示、手动检测及错误状态。此测试使用夹具，没有复用客户凭据。用户网络与后续发布状态见[进展](../../../../progress-log.md#residential-relay-20261122)。
