# Agent Note: 从节点管理删除已退役的自建线路记录

Status: implemented

## Problem

节点管理逐项展示公开入口、机器后端和独享别名。两次美国出口退役后，旧记录仍占列表空间。

## Decision

按生产只读清单和退役决定定向删除 38 条。事务内复核节点身份、授权、机器启用、存续子节点、独享占用和探针引用。核对保留节点的配置，先保存一致性备份。

## Alternatives considered

按显隐开关批量删除会影响公开线路的隐藏后端。筛掉所有停用项会掩盖保护器暂时撤下的第三方线路。

## Consequences

13 个旧入口、13 个后端和 12 个独享别名列入清理。删除登记后，旧脚本无法按原 ID 重跑当年的拓扑验收。数据库备份可追溯旧配置，账务和探针历史继续按原 ID 保存。仅在后端及采样源同时退役时解绑停用出口的引用；普通美国线的两个在用后端仍保留。没有探针覆盖的退役入口如有旧监控映射，只清理对应键。[生产结果](../../../../progress-log.md#prune-retired-nodes-20261122)

## Existing decision audit

本决定取代[普通与独享套餐拆分](../architecture/2026-10-21-owned-us-package-split.md)和[美国出口退租](../architecture/2026-10-28-owned-us-retirement.md)中保留这些撤权节点供回退的选择。[第三方线路](../architecture/2026-10-21-tiered-upstream-route-family.md)的 41 对节点在这一轮保留。其后用户明确要求[整组退役](./2026-11-22-retire-third-party-routes.md)。

同批退役节点对应的七云美国机器 SID 4–11 可按 [定向清理脚本](../../../../.docker/production/prune-retired-machines.py)移除面板登记。通用删除接口会主动解绑节点，这次要求只删闲置记录，因此在写事务内逐台核实名称、到期备注、最后上报及节点、入口监控、出口和代理库存引用。该批操作单独回读 SID 3。用户随后指定[退役香港线路与机器](2026-11-23-retire-qiyun-hk.md)。机器删除按外键清理该机器的负载历史，原登记可从操作前的私有备份追溯。

用户随后确认机器 15（美国 CN2）与 16（Windows）都已无用。两台机器单独执行同一套面板引用检查。Windows 的预期状态为禁用且从未上报，CN2 对应的历史固定出口 #17 可以停用保留，有分配或处于备用状态时会阻止清理。
