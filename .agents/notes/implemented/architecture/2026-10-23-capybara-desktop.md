# Agent Note: 卡皮巴拉桌面客户端与独立账号状态

Status: implemented

## Problem

用户在通用 Clash 客户端中需要刷新订阅才看到额度耗尽，无法区分套餐、节点和本机代理问题。用户批准开始 Windows、macOS、Linux 自有客户端，品牌为卡皮巴拉，并要求水豚图片和首页。

## Decision

在 desktop/capybara 建立 Tauri 2 / React 桌面端，复用 Mihomo 代理内核和已有 Desktop API。首版提供登录、系统安全存储续期令牌、独立轮询套餐状态、配置校验、一键系统代理、线路选择和明确错误提示。采用独立应用标识和端口，不修改用户既有 Clash 配置。

账号请求由 Rust 发起，禁用系统代理和跨域重定向；密码只用于登录，访问令牌只保留内存，续期令牌写入系统凭据库。刷新串行化，轮换结果保存失败时不继续使用旧令牌。macOS 启动与后台凭据操作静默执行，用户主动恢复/登录/注销才允许系统授权，见[钥匙串交互决定](../bug-fix/2026-10-25-capybara-keychain-prompts.md)。首页每 30 秒查询额度，并显示最后同步时间；失败只标记未知，不将旧额度推断为可用。连接前重新核对资格。服务端计费上报仍可能有延迟。

首版使用系统代理；TUN 的独立特权服务、签名和三系统权限验收另属后续能力，不提供无效开关。Linux 系统代理先支持 GNOME/gsettings。退出或核心崩溃恢复原代理，恢复失败保留修复记录并展示错误。首版安装包为明确标识的测试版，未配置代码签名、公证与签名更新链前不承诺正式自动更新。

桌面版本标签使用 `capybara-v*`，PHP 镜像版本计算排除此命名空间；发布命令显式锁定当前 fork，避免 GitHub CLI 默认选择上游仓库。桌面构建资源不进入 PHP Docker 上下文。

官网下载入口由[卡皮巴拉客户端下载](../../implemented/feature/2026-10-23-capybara-client-downloads.md)接管：电脑优先自有客户端，手机与原 Clash 保留第三方流程，复用已发布安装包。

## Existing decisions

检索活跃笔记：Clash Meta DNS 修复部分重叠，继续复用服务端规则与 DNS，不在本任务重写节点；网站独立入口部分重叠，只使用现有 HTTPS API。其他节点部署、香港未提交记录与本任务无关。后端已有桌面认证、设备限额和额度接口，不重复实现账号系统。

关闭窗口与退出由[自启与后台运行决定](../feature/2026-10-26-capybara-background-startup.md)区分：窗口关闭仅隐藏，托盘或系统明确退出才执行恢复代理和停止内核；自启由用户开启。

## Alternatives considered

- 完整 fork Clash Verge Rev 能复用特权服务和高级设置，但新增的第三方 UI、服务标识和更新渠道需要整体拆分；首版面向自有账号的简单路径，采用自有界面和成熟 Mihomo 核心。
- 单纯缩短订阅刷新间隔改动小，但无法可靠区分账号异常，也仍依赖外部客户端如何展示；独立账号状态接口是本任务选择。
- 从头实现代理协议能完全控制实现，但维护与兼容代价过大，因此复用固定版本内核、保留许可证并校验下载摘要。

## Verification

前端类型检查和生产构建通过；6 项状态测试覆盖耗尽、离线、到期、未知资格、低余额与无虚构数据。5 项 Rust 测试覆盖续期轮换、失效注销、凭据写入失败的撤销、错误脱敏、配置限制，以及固定 Mihomo 二进制的控制接口鉴权、错误配置不替换已运行配置和成功热更新。

后端 Desktop 37 项测试 / 287 断言通过，包含无需刷新配置即可查询耗尽/重置后的状态，以及内核版本独立于应用版本。PHP 8.5 产生既有依赖弃用提示，未据此声称全部依赖已兼容。Playwright 验证登录、深浅主题、窄窗口与耗尽提示置顶；网页模拟状态明确标注，不能代替真实账号与操作系统代理验收。本地 macOS DMG 已构建，三平台 CI、Release 和真实用户验证状态见 progress-log.md。

## Consequences

账号状态不依赖订阅快照，用户能看到不可用原因；系统代理主进程之外增加独立管理进程，保留恢复记录，增加了生命周期和各平台设置适配的维护成本。状态查询禁用系统代理，但不能绕过其他软件的 TUN。内核版本和数据文件固定并验证摘要，随安装包提供数据库，避免首次连接时临时下载。

首版不含 TUN、KDE 系统代理、ARM Windows/Linux 安装矩阵和签名自动更新。测试版不具备 Developer ID 公证或 Windows 发行者签名。真实账号、系统代理权限、安装升级、休眠与网络切换仍需三系统验收，不把构建通过写为这些使用场景均已通过。没有生产部署。

首版暂不提供签名更新的边界由 [alpha.3 更新决定](../feature/2026-10-24-capybara-updates.md)部分取代：每六小时检查，用户确认后验签安装；DEB 仍交由系统安装器。原有 TUN、发行者签名和公证边界继续成立。

浏览器登录入口由 [alpha.6 授权决定](../feature/2026-10-25-capybara-browser-login.md)接管：新客户端不再收集官网密码，复用浏览器会话，系统凭据库约束继续成立。


套餐入口在 alpha.8 由[客户端套餐购买决定](../feature/2026-10-25-capybara-store.md)扩展为本地选套餐/下单，实际支付仍使用服务器既有支付服务与外部支付页/二维码；原生凭据、系统代理和设备规则保持原边界。


首页和节点入口在 alpha.11 由[山水首页决定](../feature/2026-10-26-capybara-scenic-home.md)调整：独立线路页移除，实际节点选择集中在首页；连接资格、原生凭据和代理生命周期保持原契约。
