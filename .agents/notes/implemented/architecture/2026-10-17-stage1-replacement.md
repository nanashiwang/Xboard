# Agent Note: 第一阶段入口替换与 SSH 防爆破

Status: implemented

## Problem

用户指定新服务器承担 VPN 第一阶段，并要求防止 SSH 爆破。原香港入口同时承担 TLS 终止、加密中转和香港出口，替换入口不能改变既有订阅、用户身份、套餐权限或出口 IP。

## Decision

第一阶段使用用户指定的新服务器，保留原域名、公开节点 ID、UUID、权限组和父子后端关联。新入口通过独立的 wg-vpn-stage1 隧道连接全部 13 个原出口，精确 /32 路由不改变机器默认出口。原香港机器仍承担香港出口，旧入口与旧隧道保留，允许 DNS 缓存过渡及局部回退。

新机 SSH 保留已有密钥与 22 端口，只接受公钥，关闭密码、键盘交互认证和 X11，限制认证尝试与未认证连接。默认拒绝入站防火墙限制服务暴露，Fail2ban 对重复 SSH 失败执行临时封禁。服务启动依赖防火墙加载成功；修改前备份并使用限时安全回退，独立连接验收后取消回退。

先按新 IP 和原 TLS SNI 验证完整代理链路，再切换 DNS，最后按实际域名重复验证。节点仅重命名入口后缀，其他关键字段经前后比较保持一致。证书、临时运维凭据及回退规则见[运维手册](../../../../docs/zh-CN/installation/vpn-stage1.md)。

## Existing decision audit

已审核本地此前未提交的自有香港入口架构笔记及[香港入口文档](../../../../docs/zh-CN/installation/hong-kong-ingress.md)：鉴权、出口隔离和套餐约束继续复用，入口位置与加密路径由本篇说明。此前笔记和文档的未提交改动保留原归属，不纳入本次提交。本篇与[项目工作流](../process/2026-10-17-project-decision-kit.md)在协作流程上关联，后者不需要变更。

## Alternatives considered

- 仅改 SSH 端口可以减少扫描噪声，但不能消除密码猜测，还增加管理客户端维护负担，因此保留 22 并收紧认证方式。
- 仅安装 Fail2ban 改动较少，但不能防止意外服务暴露，因此同时采用公钥认证和默认拒绝入站规则。
- 复用旧隧道或直接切换域名更快，但会同时改动原入口的回退路径，因此采用新端口和地址空间，完整验证后切 DNS。
- 删除旧香港入口可减少维护范围，但 DNS 缓存中的客户端仍可能连接旧 IP，因此保留它作为过渡和回退点，不把清退混入本次迁移。

## Testing

切换前按新 IP、切换后按域名分别通过 13 条严格 TLS HTTPS 出口与 UDP DNS；第二个付费用户首末两条通过，错误 UUID 被拒绝。套餐节点数为 14/15/16/17，CF 基础备用、13 台后端公网端口隔离和原服务检查通过。新机密码认证拒绝、Fail2ban 实际封禁/解封、有效 SSH 配置与持久化服务检查通过。完整执行证据及首次失败修复记录见[进展记录](../../../../progress-log.md)。

## Consequences

新入口仍是主线路单点，备用入口和局部回退路径保留。入口域名保留 hk 仅为兼容，不表示新服务器地域。密钥登录和封禁降低 SSH 猜测风险，不保证抗 DDoS 或无法识别。未做大陆运营商测速、长期观察、整机重启恢复或流量计费对账；原 sing-box 订阅模板的 legacy 格式兼容待办仍需独立完成，不能用本次专用探针代替所有客户端验收。
