# Agent Note: 四档套餐的自建与第三方拓展线路

Status: implemented

## Problem

用户要求四档普通套餐同时提供自建与第三方线路，价格越高可选节点越多。此前只完成规划，截图实际只有 6 条自建，却以为已经有 14 条；用户明确要求实际接入。上游 46 个条目中只有 41 条代理线路，另外 5 条是提示，不能作为已交付数量。

## Decision

2026-10-22 在现有第一阶段服务器运行独立机器 21 / xboard-extension 服务，通过 Nginx TLS → 回环 VLESS 后端 → 指定第三方出站转发。复用 ServerService 的 custom_outbounds/custom_routes、原 UUID 鉴权和 TrafficFetchJob，单进程管理 41 个后端，不在低内存 FriendHosting 节点叠加进程。41 个公开节点与 41 个隐藏后端一一对应，后端端口 37001–37041 仅回环可达；公开/隐藏 ID 与配置边界见[分配清单](../../../../.docker/upstream/allocation.json)及[运维](../../../../docs/zh-CN/installation/upstream-extension.md)。

轻量/标准/进阶/旗舰累计新增 8/16/28/41 条，叠加每档 6 条自建，实际订阅为 14/22/34/47 条。权限组分别累计 1–4、2–4、3–4、4，并允许内部监控组 6；独享组 5 不加入，原 11 个美国固定出口池不变。原售价、额度、限速、设备限制、身份与订单保持。本次接入时保留自建名称，并用地区、U 编号和倍率区分拓展；这一命名决定已由[统一节点名称与家宽倍率](../../implemented/simplification/2026-10-22-node-names-and-residential-rate.md)部分取代。当前客户端名称为“国家或地区＋两位编号｜倍率×｜可选家宽/原生IP”，不再通过自建、拓展或 U 编号区分来源；后台 ID、标签、权限和客户端默认策略组边界继续保留。

两组消耗同一用户套餐额度。41 条拓展中，原上游标注 2x/5x 的对应节点按 2x/5x，其余拓展按 1x；公开与实际计量后端倍率一致。全部 13 个自建美国出口另按后续决定统一为 2×，包括普通套餐两个和固定池十一个；“家宽”标记采用用户定义，不宣称独立住宅 IP 认证或物理独占。上游凭据只在私有服务器配置，订阅仅包含用户自己的身份。固定路由失败不回退 DIRECT；公共入口仍共用，不代表两套独立容灾网络。

### 证书与连接地址

3 条 CDN 使用公共 CA 校验。38 条自签名线路采用首次信任的证书公钥固定；非 QUIC 出站把实际连接地址与公钥配对，避免同一域名轮换到不同证书。28 条 IPv4 TCP 端点另从面板服务器比对相同；其余 IPv6/QUIC 未取得独立供应商指纹，不能称作公共 CA 或供应商认证。所有实际出站均无 insecure=true，后续换证必须重新验收，不自动信任任意新公钥。

### 运行时 AnyTLS 身份检测

仓库 [guard.py](../../../../.docker/upstream/guard.py) 以 `approved.private` 和 [allocation.json](../../../../.docker/upstream/allocation.json) 的 key/后端/公开 ID 交叉限制范围，只握手检查其中 28 条 AnyTLS。信任来源沿用历史 `pinned.private` 行的 key/ip/port/sni/pin：固定 IP 与独立 SNI，pin 为已批准叶证书 SPKI DER 的 SHA-256/Base64；算法与 [sing-box 公钥固定定义](https://sing-box.sagernet.org/configuration/shared/tls/#certificate_public_key_sha256)一致。当前证书只能用于比较，不能生成或更新批准基线。新加坡 U04/U05 分别为 365→366、367→368。

默认保护流程在订阅抓取成功或失败后都执行身份检查，防止 24 小时元数据宽限掩盖 `unrecognized remote public key` 对应的身份拒绝。公钥不匹配、TCP 不可达、TLS 失败、超时、工具/证书解析失败以及缺失/重复/错误映射都不能算通过；仅将对应批准节点交给原撤下事务。原额度、到期、来源变化理由优先，身份检查详情独立保留。非 AnyTLS 不宣称已验证，未知 key 不扩充检测或撤下范围；损坏的范围清单使批准项失败关闭。成功只说明该次公钥匹配，不重新启用节点，不代表 AnyTLS 密码、目标 HTTPS 或公开路径已恢复。

`--check-identity` 是只读入口，可用 `--key U04 --key U05` 收窄诊断，不抓订阅、不写状态、不调用 Docker/数据库。检测使用 Python TLS 收集证书后显式比较批准 pin；采集阶段不做公共 CA 验证，但未匹配绝不判成功，不发送 AnyTLS 账号或应用字节，也不修改业务出站 TLS 配置。最多 8 并发，每项 TCP/TLS/证书转换共用 5 秒预算；输出只有 key/ID/固定错误分类，不输出端点、SNI、摘要或异常原文。私有映射和批准文件由运维维护，不提供自动采信脚本。部署文件、依赖及服务超时前置条件见[运维](../../../../docs/zh-CN/installation/upstream-extension.md#运行时-anytls-公钥检查仓库已实现未部署)。

### 使用限制与维护

41 条最终 HTTPS 通过，33 条 UDP DNS 通过。U01/U02/U03/U20/U21/U22/U23/U24 的美国 UDP 对两个公共 DNS 未通过，接入验收时名称附带“UDP受限”；后续统一命名已移除该尾缀，限制仍保留在分配清单和运维记录。U36–U39 同样移除名称中的轻量使用提示，每条共享双向 2 Mbps 上限保持；tc 仅作用于四个回环端口，MTU 显式 65536，不替换主接口队列。policing 会造成重传，一次 2 MiB 下载未在 40 秒完成，不能把上限或短请求成功称作持续速度保证。

面板每 5 分钟读取受限订阅，校验已批准源名称及配置指纹、额度和到期。失效、消失、歧义或变更条目仅撤下对应拓展公开/后端；新增未知条目忽略，变化后的端点/凭据需重新测试后人工重新发布。保护程序不自动恢复撤下项。短暂获取失败沿用已知配置，24 小时没有有效元数据或进入已知到期窗口则撤下全部拓展。不是未经测试的原始订阅自动覆盖。

独立探针 2 从面板服务器每 300 秒检查全 41 条真实公开路径，每天每条各 64 KiB 上下行完整性检查；原 NAS 探针 1 的 17 条保持。连续两轮 41 条均按现有规则达到 healthy，82 项 64 KiB 上下行完整性检查通过，不手工标绿。所有用户共用一份上游额度和到期，仍需维护续费与供应商共享/并发限制；41 个名称不代表 41 个独立出口或容量。

## 人工恢复与候选承诺

用户在2026-10-27明确授权核实后的生产公钥和地址修复、逐条验证及回退。复用原首次信任边界：源HTTPS订阅证明其声明的端点/凭据，跨网络一致与严格候选pin业务成功支持本次有限人工TOFU复验，不冒充供应商独立签发指纹。优先在源DNS候选中找到原pin，仅更新IP；没有原身份时逐项审定候选，禁止扫描结果直接覆盖批准基线。

[prepare.py](../../../../.docker/upstream/prepare.py)与[快照助手](../../../../.docker/upstream/snapshot.php)是只读入口：以allocation、approved及私有manifest核对41对映射，捕获完整配置状态摘要以识别并发漂移，按精确来源名/指纹检查额度有效性。31条TCP、7条QUIC和3条公共CA观察不发送代理身份或应用数据；候选承诺对key/IP/port/SNI/pin规范JSON取SHA256，公开报告只含承诺、来源名摘要、布尔和分类；快照前置失败仅返回白名单布尔及有界数量以定位存储/结构，不输出原始异常或映射内容。私有计划在面板专用目录0700/0600，观察值不自动成为信任值；Hysteria2使用固定依赖源码构建的仅证书QUIC观察器，严格核对二进制SHA；公共CA线路保持系统CA与SNI验证，观察pin不转为CA线路的固定pin。容器丢失manifest时拒绝继续；生产原映射改从固定宿主持久私有文件读取并验证，缺失不生成。[工作流](../../../../.github/workflows/upstream-maintenance.yml)复用已有生产SSH身份，仅允许master和明确阶段选择，输入经结构化control校验后传递，不插入shell。撤下/隐藏应用/公开/回退分步执行，公开路径验收绑定维护回执与实际完整配置摘要。

[维护driver](../../../../.docker/upstream/maintain.py)及[事务助手](../../../../.docker/upstream/recovery.php)落实在线SQLite备份、限定字段事务、原状态/候选/计划摘要绑定；分步withdraw、apply_hidden、publish与rollback，候选不在CLI接收自由IP/公钥。私有映射、来源、全配置漂移拒绝继续；intent无receipt不自动重放。回退只恢复本次出站且维持撤下，不能整库覆盖订单/流量。生产执行还需人工核定候选、私有pin映射一致及真实公开路径验收。只读准备初次37项专项CI通过；前置失败后补固定阶段白名单与来源内容摘要交叉核对、多播/保留地址拒绝，38项本地Python回归和PHP语法通过，生产候选/变更/公开路径结果以[进展](../../../../progress-log.md#2026-10-27生产外接线路人工恢复)为准。

容器及宿主manifest都已确认缺失时，现存approved与固定allocation仍提供原41对ID和来源指纹。[scope_restore](../../../../.docker/upstream/scope_restore.py)通过只读DB归属和完整状态摘要先出具私有审计，再由操作者对具体ID/SHA显式重建最小scope；此为重新确认授权范围，不宣称找回原文件。重复来源、错配、漂移和任何现存目标都拒绝，原子no-overwrite并保留intent/receipt；guard/prepare仍不自动fallback。源、公钥、节点配置和自建范围均不由该操作变更。

撤下请求与最小manifest通过PHP stdin传输，避免应用容器重建丢失私有文件后使保护失效。生产部署前仍须核对完整28条当前pin、只读检查及systemd超时预算，不得跳过运行时检测。

U01的来源指纹变化通过“当前source仅还原server为原生产server即可精确命中旧approved SHA”证明为单字段地址变化。[受限接受工具](../../../../.docker/upstream/accept_source_address.py)仅允许显式U01/计划SHA/新来源SHA，fresh来源、两次完整DB状态、批准文件与manifest均固定，先备份再仅更新source_sha256；不修改节点、公钥或其他来源字段。它是本次地址修复的人工步骤，不是自动跟随订阅；旧准备计划因批准字节变化失效，必须重做候选准备。

面板当前无IPv6，因此有限人工候选可由入口与独立IPv6观察点提供同一身份、有效期和来源DNS证据。新增[加密导入](../../../../.docker/upstream/import_reviewed.py)以计划绑定的RSA-4096-OAEP-SHA256只传输身份密文；逐项来源/端口/SNI/摘要与两处证据校验，全41来源、额度及两次完整DB状态核对后，仅生成保留原2小时有效期的新私有计划。它不修改信任或自动选择，不把外部DNS观察标成面板观察；公共CA两处均验证且执行时仍不加pin。复用相同证据重新加密也不能重放，未知结果保留私有intent。

固定探针既有专用服务读组不应误判为不安全：公开验收只读接受root持有0600，或0640且gid精确匹配固定已加载、非DynamicUser服务的有效组；通过O_NOFOLLOW、inode/mtime/ctime/内容和前后服务身份检查，不更改权限或读者。其余私有计划与缓存继续0600。[权限修复](../../../../.docker/upstream/secure_probe_config.py)先确认固定服务静态root、原文件归属/结构/inode与内容，再仅fchmod0600并保存私有操作元数据，不更改URL/token或服务。运行时身份检查须在具备实际上游地址族的网络执行；当前IPv4面板不能直接承载含IPv6出站的默认runtime检查，否则会保守撤下本可用线路。

维护契约接受sing-box既有严格默认：`tls.insecure`省略等同false，保存时仍保留省略；显式null/true/非bool一律拒绝。Python与PHP不能因序列化omitempty差异把已严格试连的配置误判为关闭校验。

## Alternatives considered

- 四档都开放全部 41 条省去分档，但不满足用户的价格差异；采用累计 8/16/28/41。
- 直接发上游订阅最省部署，却暴露共享身份并绕过套餐鉴权和计费；采用服务器端出站。
- 为证书问题全局关闭验证可以凑齐连接数，但失去证书约束；采用明确的首次信任公钥与端点配对，记录其信任边界。
- 持续追随上游 DNS 轮换会遇到不同公钥；绑定验收过的地址更可核对，代价是轮换/换证需要维护和复验。
- 原计划自动验证并热更新凭据需要完整候选轮换系统；当前采用自动识别变化并撤下、人工复验发布，避免无验证更新到客户路径。
- 仅依靠 JSON 指纹或通用 HTTP 健康探针省去身份握手，但无法区分本次字段未变的公钥拒绝与 TCP 超时；补上独立的固定端点 SPKI 检查，保留真实公开路径探针作为另一层验证。一次握手失败即撤下可能受检测机网络影响，代价通过人工复验承担，不以重试宽限放过身份异常。
- 复制完整出站配置可以直接启动内核验证，但需要读取上游密码；本次复用既有无密码的 pin 映射，只做 TLS 身份比较。Python 标准库结合已安装 OpenSSL 转换 SPKI，避免新增证书库；工具缺失明确失败，不能跳过。

## Consequences

用户可继续使用原订阅，刷新后获得明确分档的两类线路。来源账户、统一入口与证书维护仍是共同依赖，新增节点数不等于带宽增长。8 条美国 UDP 受限、4 条低流量限速和首次信任证书边界必须保留在运维记录；长期性能、并发容量和大陆运营商体验未验收。

自动保护只撤下批准拓展映射，不修改客户或自建配置；轮询存在约一个周期延迟。新身份检查增加 TLS 探测流量与对检测机网络/OpenSSL 的依赖，5 秒单项期限可能保守撤下慢线路；未部署前不会改变线上撤下行为。现有节点停用后最后一批流量上报可能被 enabled 鉴权拒绝，常态计量通过不等于停机结算无损。配置更新后需重新验证才能重新公开。回退范围与私有备份路径见运维文档，不能整库恢复覆盖后来订单和使用量。
