# Agent Note: 家宽资产共用第一阶段固定入口

Status: implemented

## Problem

0.1.17 的普通订阅中转与独立直拨无法让仅有家宽的用户稳定连接。用户要求两种账号走相同的第一阶段和已购出口。

## Decision

原生客户端从本人资产接口取得认证和固定端口。内核的 HTTP/SOCKS5 上游是当前连接独占的回环端口，桥接器仅拨 node.lumavia.fyi 的 WSS 固定路径。入口用独立受信证书验证下一跳的身份，每个路径只映射一个 PX 端口。PX 的转发服务仅接受第一阶段的来源，交给原端口执行认证、租约和限速。普通订阅配置不参与选路。握手重置可在发送代理字节之前重试一次，已经转发的请求不重放。

断开时中止监听及所有活动连接。资产到期、修订或账号撤销沿用原有关闭逻辑。系统代理启用前核对实际出口和 Google 204，首页复检同一内核。

## Alternatives considered

[0.1.17 普通订阅中转](../bug-fix/2026-11-22-residential-relay.md)可复用已有节点和真实出口检测，但增加普通套餐依赖并可能多经过一个出口。直接拨号已在用户网络复现重置。入口开放通用 CONNECT 需要另行维护身份与可访问目标，逐端口固定映射可以复用[家宽销售与租约](../feature/2026-11-18-residential-proxy-sales.md)的现有判定。

## Consequences

两个协议共用现有入口的 HTTPS 443，无需额外购买普通流量或复制第二份用户认证。维护者需要维护每台 PX 的独立证书和端口映射。第一阶段不可达时连接仍会失败。原先手工使用的家宽代理端口可继续独立使用。

## Testing

固定内核配合 WebSocket 夹具验证首次握手中断后的 HTTP 和 SOCKS5 认证、目标地址和网页响应。20 条映射的目标与证书配置逐条核对，本机原生桥到生产 PX-1 的认证协商及断开清理单独验证。生产账号验收及版本交付见[进展](../../../../progress-log.md#residential-stage1-20261122)。
