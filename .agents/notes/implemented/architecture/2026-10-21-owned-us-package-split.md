# Agent Note: 自建美国出口按普通与独享套餐分离

Status: implemented

## Problem

用户要求四档普通套餐仅保留两个自建美国节点，其余自建美国出口用于独享套餐。现有 16 条美国普通订阅记录对应 13 个去重出口，其中 CF 的四条记录使用同一 IP；全部 13 个出口此前也接入固定池。直接将旧公开记录权限改成独享组会绕过每账号固定分配，直接撤掉普通权限则会使现有监控账号失去探测资格。

## Decision

2026-10-28 的[美国出口退租与替换](../../implemented/architecture/2026-10-28-owned-us-retirement.md)部分取代本文的物理出口数量与对应关系：普通美国01/02改为 #324/#323，固定池仅保留出口14（216.36.108.173），原权限隔离、每出口五名额与2×计量约束保留。以下原选择与验收记录作为历史依据。

普通组 1–4 保留美国 06（公开 319 / 后端 332，38.244.38.191）与 CF 基础备用（148 / 147，192.204.56.29），提供不同入口的两个美国出口。选择时二者有新鲜成功探测且无固定账号或订单预留占用；不是全国网络性能排名。对应固定池出口 11、18 停止分配，别名 345、352 隐藏，其余 11 个去重美国出口仅供固定池账号与监控身份访问。原固定账号绑定不主动迁移，仍按每账号固定一个出口、每出口五名额运行。

同 IP 的 CF 标准/进阶/旗舰记录 150、156、158 及后端 149、155、157 不提供新增容量；撤下客户可见性、清空权限并停止重复后端，保留记录便于局部回退。仅移除这三条重复探针，其他探针继续保留。

创建仅供监控的权限组，迁移现有专用监控账号 33（非管理员、plan_id=null），保留 UUID、令牌、额度和有效期。原公开源记录可保持 show=true 但仅给监控组，用于既有质量探针与健康检查；固定客户继续使用有 dedicated_exit_id 的订阅别名。独享后端仅组 5 和监控组，普通保留后端仅组 1–4 和监控组，香港及非美国出口追加监控组而保留原客户权限。

四档普通套餐调整后均为 6 条自建线路：美国 2、香港/日本/荷兰/罗马尼亚各 1。第三方分配仍为累计 8/16/28/41，未来目标总数改为 14/22/34/47；拆分时第三方尚未接入，后续实际接入见拓展决定。本轮不改变客户套餐价格、流量、设备限制或独享销售上限与上架状态。

## Existing decision audit

- [自建固定出口池](../../implemented/feature/2026-10-19-owned-fixed-exit-pool.md)部分被本决定取代：从普通与独享共享全部美国出口变为两组分开；固定分配、容量和真实健康规则继续保留。
- [第三方分档提案](./2026-10-21-tiered-upstream-route-family.md)部分重叠，仅修正自建基数及目标总数，第三方范围与待验事项不变。
- [FriendHosting 接入](../../implemented/architecture/2026-10-21-friendhosting-japan-node.md)不改变其普通套餐访问范围；[质量探针](../../implemented/feature/2026-10-18-node-quality-probes.md)复用独立监控账号，增加专用权限组避免依赖普通套餐。
- 本地此前未提交香港入口笔记和文档保持原归属，无同名待实施提案。

## Alternatives considered

- 只移除普通订阅里的节点最省改动，但复制旧链接仍可能认证，必须同时撤销后端普通组授权。
- 把全部旧公开源直接改为组 5 可以一次显示所有线路，却绕过固定分配；保留固定别名，并把原源记录限定给监控组。
- 继续让监控账号属于旗舰组可省组迁移，但给它保留全池访问就会把普通旗舰权限一起保留；迁移已有独立监控身份，不改变客户身份。
- 保留两个同入口美国出口也能满足数量，但单入口故障会同时影响两条，因此保留第一阶段和 CF 各一条；CF 重复入口不重复计数。

## Testing

应用前六条保留普通线路的真实 HTTPS 出口 6/6 通过。事务核对配置指纹、13 个原池映射和两保留出口无占用；先生成 SQLite 一致性备份（integrity_check=ok）与字段回退快照，再应用权限、监控组和停用项。事务内确认客户套餐条款与当前固定绑定未变。原校验把 allocation_version 锁计数及 updated_at 混入配置指纹，导致首次应用在实际修改前回滚；改为只比较业务配置字段后，候选差异相同并通过。PHP 标准输入执行时无 STDERR 常量，错误捕获使用 php://stderr；未据退出码 0 声称应用成功。

新增回归覆盖监控组可探测、普通与固定身份隔离、健康判定和全量同步移除旧普通授权。相关 12 项测试 / 99 断言通过（本地 PHP 8.5.9，含一项现有弃用提示）；Python 语法与嵌入 PHP 语法通过。生产独立内核的 48 项实际请求全部通过：13 次监控、6 次普通用户、1 次固定出口和 1 次香港备用成功；26 次越权及 1 次无效 UUID 被拒绝。固定客户对两个普通美国出口也被拒绝，旧重复 CF 入口已不能认证。

Clash Meta 与 Shadowrocket 两种实际订阅输出覆盖四档，共 8 项检查全部为六条；11 个池后端均无普通组账号，监控账号有授权。监控组只有原账号 33，未关联销售套餐；17 条配置无错误并获得切换后的新鲜真实样本，机器 2 只运行 CF 基础后端 147。25 个既有账号的身份、余额与权益字段对比数据库备份保持，唯一预期变化是监控账号的 group_id；固定订单保持。

本轮事务不改固定账号绑定。后续原健康调度按 exit_failed 自动迁移已有账号，验收时订阅为分配的美国出口与香港备用，两者实际成功；不以本轮分组操作宣称固定 IP 永不变化。池健康继续按真实 NAS 探测判断，不强制 healthy，不把 11 个已配置出口说成同时健康。详见[进展记录](../../../../progress-log.md#2026-10-21自建美国出口按套餐拆分)。

## Consequences

普通套餐每档保留美国两条与非美国四条；独享池拥有其余 11 个美国出口，仍为每出口最多五名固定套餐账号，售价、总销售上限和上架状态不变。保留专用监控组使故障检测与销售套餐权限分开，但管理员仍会看到只供监控的旧源记录，不能按 show=true 误认为普通用户可用。

权限撤销会让旧节点链接失效，客户端需刷新订阅并选择保留线路。当前电脑默认 utun 代理在切换后不能建立 SSH 连接，绑定 en0 的独立管理连接正常；后续验收使用独立连接，没有修改系统代理或伪装成功。

配置备份位于生产容器 storage/app/backups/us-split-20261021/，包含受限权限数据库、rollback.json、preview.json、applied.json；执行脚本位于宿主 backups/us-split-20261021/。恢复时仅还原本轮节点/监控/池字段并重新同步用户与机器，先核对固定绑定；不得整库恢复覆盖后来订单与用量。停用的两个池项仅在重新通过真实健康检查后恢复分配，监控组必须先迁回后才能移除。

NAS 网络有间歇失败，长期性能和全国运营商体验未由短请求证明。角色隔离不等于一人独占物理服务器或住宅 IP 认证。美国拆分当时没有接入第三方；后续拓展接入状态由拓展决定记录。
