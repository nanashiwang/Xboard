# Agent Note: 注册滥用分层防护

Status: proposed

## Problem

2026-11-03 用户反馈近期批量注册。本轮只读检查生产后台、SQLite、邮件及 Nginx 日志；完整证据与限制见[进展](../../../../progress-log.md#2026-11-03批量注册排查)。63 个同后缀账号集中出现，现有邮箱验证不足以区分自动收码与正常注册。禁止据此推断身份、认定该邮箱域所有用户恶意，或把当前配置当成所有历史时刻的配置。

## Proposal

1. 先核准旧域、Go、Cloudflare、跳板到 Laravel 的可信代理链。来源头只由可信代理设置，拒绝客户端伪造；原始日志中的 CF 地址不用于封禁或单独评估攻击者数量。
2. 保留邮箱验证和关闭试用的现态。复用 IP 注册开关作为基础限制，初始候选沿用已有 3 次/60 分钟；这只是起点，结合共享出口正常用户数据调整。新增长期窗口与跨 IP 的邮箱域异常信号，不能只靠封 IP。
3. 对本次集中滥用的 `fldubai.com` 提议暂缓新注册与新用户发码，设置可撤销例外和到期复核；避免影响已有用户登录、找回密码和付费权益。现有系统只有白名单，定点拒绝需要新增后端策略，不能宣称已具备。将常用邮箱白名单作为更严格备选，默认不采用，以免拒绝正常企业邮箱。其他域不能仅凭单个账号或陌生后缀加入拒绝名单。
4. 同时保护 `passport/comm/sendEmailVerify` 和 `passport/auth/register`：按可信来源、规范化邮箱分别计数，发送验证码有短期与日额度、失败验证有次数上限；前置原子配额、并发锁/一次性消费，覆盖多 worker。当前成功注册后 Cache get/put 存在竞态；每邮箱 60 秒冷却无法限制更换邮箱。关闭注册时只阻止新用户注册发码，已有用户密码恢复继续可用。
5. Turnstile 作为后续一道防护：先处理此前验证循环，核对现用域名允许列表、服务端 hostname/action、超时与错误码、前端刷新及重试。发码与最终注册会各自校验，不能重复消费同一 token。可按风险升级验证，不把整站挑战直接叠到订阅、桌面授权或支付接口。相关规则依据 [Cloudflare token 校验文档](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)；尚未证明历史循环由 token 重用导致。
6. 增加最小注册事件审计：请求 ID、结果/拒绝原因、邮箱域与带密钥摘要、受控来源摘要、时间和关联账号 ID；不记录密码、邮箱验证码、授权令牌或订阅 URL。按域注册增速、发码/注册转化、订单与流量观察告警。已有 63 个账号先保留证据；封禁、删除和名单批处理另行决定，不自动处置。

分层思路参考 [OWASP 防自动化指南](https://cheatsheetseries.owasp.org/cheatsheets/Bot_Management_and_Anti-Automation_Cheat_Sheet.html)。具体额度是本项目待验证的参数，不是已实施承诺。

## Alternatives considered

- 只打开 IP 限制：最快且已有实现，但分散来源、低速注册和代理身份混淆均削弱效果，只作为一层。
- 立即启用 Turnstile 或全站 CF 挑战：能提高自动化成本，但此前有正常用户循环失败，且 Go 当前不经过 CF 代理；应先验证组件流程，不影响机器接口。
- 只允许 QQ/Gmail 等少数邮箱：可快速挡住本次后缀，但误伤企业邮箱且攻击者可换到常见邮箱，优先定点策略与行为限制。
- 批量删除同域账号：清理直观但会丢证据，不能阻止再注册，也无法由域名独立证明每个账号恶意；暂不执行。

## Acceptance criteria

- 生产变更前核实可信 IP 链，覆盖伪造转发头、CF/跳板、IPv4/IPv6 和旧域路径。
- 自动化回归覆盖并发阈值、换邮箱发码、验证码过期/错误/重放、正常注册与已有账号找回密码，计数拒绝不创建账号或额外发信。
- 浏览器验证正常用户完整注册、慢网/失败重试、桌面注册返回；Turnstile 成功/过期/重复 token 分开覆盖。
- 提供具体配置 diff、回退值及脱敏命中统计；上线后观察正常转化与误拦截，不能以 HTTP 200 或单次验证码通过代替业务验收。

## Risks

共享出口可能误限正常用户，域名策略可能误伤企业/小众邮箱，攻击者可换域或更换 IP。审计数据需要最小化和短期留存。当前只读证据不能确定操作者身份、代理服务、收件箱控制方式或最终用途；禁止用推测代替调查结论。
