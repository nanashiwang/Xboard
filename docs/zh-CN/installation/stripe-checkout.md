# Stripe Checkout：人民币记账、美元付款

站点套餐、优惠券、余额和佣金继续以人民币分记账。Stripe 支付通道可选择美元；首次支付报价会保存人民币应付、美元应付、汇率和成本预算，后续回调按保存的美元金额核验，不按最新汇率重新计算。

## taige 当前美元定价

2026-09-18 配置：固定结算汇率 `1 USD = 6.7075 CNY`，参考 Frankfurter 在 2026-09-17 发布的报价。采用固定、可手动调整的结算汇率，不称为银行实时换汇价，也不在支付时依赖外部汇率接口。调整仅影响尚未报价的新订单。

美国 Stripe 标准线上卡成本为 2.9% + $0.30，国际卡另加 1.5%。当前以国际卡合计 `4.4% + $0.30` 作为美元售价的成本预算：

```
美元售价 = 向上取整至美分((人民币应付 / 6.7075 + 0.30) / (1 - 0.044))
```

这是含支付成本预算的美元售价，并非承诺每笔交易实际手续费等于该预算。美国本地卡、非卡支付方式、定制费率、退款和争议等费用可能不同；用户发卡行收取的跨境/换汇费用也不由站点决定。不额外叠加 Stripe 的商户换汇费，因为本配置用 USD 扣款、USD 结算。

若日后按卡片实收附加费，需另行按账户所在地和卡组织要求实施上限、适用卡种及披露；不能仅改名称就认为不受附加费规则约束。本插件未启用 automatic_surcharge，也未声称已完成逐卡附加费合规计算。

## 后台设置

1. 保持站点币种 `CNY`，选择 `StripeCheckout`，收款币种选 `USD`。
2. 填写结算汇率 `6.7075`、比例成本预算 `4.4`、固定成本预算 `0.30`。通道原有的固定/百分比手续费设为 0，避免重复计入成本。
3. 使用后台的“美元商品价格映射（JSON）”保存上述清单内 `catalog_usd` 对象的 JSON。仅当应付金额与目录价完全相同时引用对应 Price；优惠或余额抵扣后的差额，在同一个 Product 下使用按报价计算的金额。
4. 填写 `rk_test_`/`rk_live_` 受限 API 密钥（推荐），或兼容的 `sk_test_`/`sk_live_`。受限密钥需要创建 Checkout Sessions、读取商品价格，以及按差额创建价格所需的权限。使用服务端受限存储，禁止将密钥写入仓库、日志或前端。测试与正式环境的商品和密钥不能混用。
5. Webhook 地址为后台生成的 `/api/v1/guest/payment/notify/StripeCheckout/通道UUID`；监听 `checkout.session.completed`、`checkout.session.async_payment_succeeded`。新建端点使用 API 版本 `2026-07-29.dahlia`，将该端点的 `whsec_` 填入通道。旧端点无需为了历史事件修改版本。
6. 完成测试环境的支付成功、取消、失败、重试与仅开通一次的检查，再开放正式通道。无密钥时不能进行真实收款联调，也不能仅凭商品创建成功判断网站已能收款。

Checkout 关闭 Adaptive Pricing，确保扣款币种为 USD；可用支付方式由 Stripe Dashboard 动态配置。付款确认前展示套餐周期、人民币参考金额、结算汇率和已含成本的美元总价。前端返回订单页不作为到账依据。

## 金额和回调

- 报价使用整数计算，避免浮点分币误差；报价表 `v2_stripe_quotes` 保存每次应付金额的首次报价，唯一键防止并发生成两个汇率。
- 重新打开同一金额的订单沿用已锁定报价；人民币应付或通道发生变化时重新报价。每日更新 Stripe 幂等请求键，允许过期收银台重新创建，美元金额仍保持锁定。
- 回调校验原始请求签名、时间窗口、环境、订单、支付通道、报价归属、人民币应付及美元实收；旧 CNY 回调仍兼容。
- 美元至少 $0.50，金额、汇率或成本预算越界时中止，不默默套用默认汇率。
- 从有手续费的支付通道切换到无手续费通道时，清除旧通道遗留的人民币手续费。

### 1.1.1 修复说明

- 修复表单编码将关闭 Adaptive Pricing 的布尔值发送为 `0`，导致 Stripe 返回 `Invalid boolean: 0`、网站无法创建结账页面的问题；现在明确发送字符串 `false`。
- 回归测试检查实际 HTTP 表单正文，覆盖人民币和美元结账，避免仅检查编码前的参数。
- 创建失败时记录 HTTP 状态、Stripe 请求编号和错误类型/参数，便于定位；不记录密钥、结账链接或完整请求/响应正文。
