# 固定分配美国出口套餐

当前生产套餐为美国独享家宽IP、59 元/月、200 GB/月、10 Mbps，不限制在线公网 IP；当前容量 5 个账号，只开放月付。公共线路与固定出口共用流量，当前 3 个自建美国出口（普通套餐 2 个、固定池 1 个）均按用户定义标为“家宽”并按 2× 计量，当前名称和倍率以[节点展示映射](../../../.docker/node-presentation.json)为准。家宽标记不是独立住宅 IP 认证，也不表示物理独占。

`.docker/dedicated/plan.json` 属于历史 1× SOCKS 出口初始化模板。`dedicated:prepare` 的后端和订阅别名仍硬编码为 1×，本轮未适配该命令；它和模板均不适用于当前 2× 自建池，不得据其重建当前生产套餐或出口。

## 复用自建后端的出口池

历史自建接入命令 `dedicated:attach-owned <套餐ID> <清单>` 默认仅预览，追加 `--apply` 才写入；价格、上架状态和套餐总销售上限保持不变。该命令仍按 1 倍率校验，当前 2× 固定池会被安全拒绝，不能重跑旧命令或旧工作流来覆盖现有池；未来新增接入需先单独适配倍率校验并完成验收，本轮没有扩展命令能力。清单包含 `probe_id`、`exits` 中的 `server_id/ip`，以及独立的 `public_fallback_ids`。先检查清单与真实出口 IP，生产清单见 `.docker/dedicated/owned-production.json`：仅保留 216.36.108.173（源 #322 / 后端 #335 / 固定别名 #348 / 出口 #14）；普通套餐使用 216.36.108.128（#324 / #337）和 192.220.24.147（#323 / #336）。其余美国出口和原 CF 备用退出授权，记录保留。香港线路作为固定账号公共备用。

客户端采用 `国家或地区＋两位编号｜倍率×｜可选属性`，自建美国显示为 `美国编号｜2×｜家宽`，不再追加自建、固定出口或入口说明。名称及实际倍率调整见[命名与家宽倍率决定](../../../.agents/notes/implemented/simplification/2026-10-22-node-names-and-residential-rate.md)；固定分配、权限、节点 ID、协议与路径保持，公开记录和负责上报的后端倍率必须一致。

出口引用 `shared_server_id` 和指定监控节点，普通前端与后端的 `dedicated_exit_id` 保持为空。新增仅供专属组的订阅记录，复用原入口路径和后端；按[2026-10-21 拆分决定](../../../.agents/notes/implemented/architecture/2026-10-21-owned-us-package-split.md)，池内后端仅允许独享组 5 与内部监控组 6；固定账号只下发到其分配的后端。原源记录只对监控组可见，普通组 1–4 不得访问。复用硬件及 IP 不等于物理独占，每出口五名额仅指该固定套餐账号。

普通美国节点为 #324 → #337 和 #323 → #336，名称沿用美国01/02，四档普通套餐各六条自建线路。固定用户为美国10（216.36.108.173）和香港01备用；一个旧绑定已迁至出口14，价格、期限和额度不改。监控账号仍为内部组6，自建探针范围收敛为三个美国出口与香港/日本/荷兰/罗马尼亚共七条。原美国节点全部撤销授权；不恢复历史清单。见[退租决定](../../../.agents/notes/implemented/architecture/2026-10-28-owned-us-retirement.md)。

健康检查复用指定探针的新鲜 HTTPS 成功与实际出口 IP，并要求后端心跳新鲜；两个不同观测时间的成功才恢复，重复读取同一观测不累加。三次连续连接失败停止分配，错 IP、过期数据、停用探针、监控账号不可用或订阅路径漂移立即使检查失败并撤销健康。NAS 网络故障也可能暂停分配；不要手工强制 healthy 或刷新 checked_at 来消除等待。

应用前生成 `storage/app/owned-fixed-*.json` 的 0600 快照，保存原权限组、监控预期出口和旧绑定清单。回退仅恢复本次节点权限及新增别名/出口；若订单已经完成，先确保账号仍有可用出口，不用整库回滚覆盖权益或新订单。 回退到不支持共享固定池的旧镜像之前，必须先按快照撤销共享后端上的专属组授权并停用新增别名，否则旧授权逻辑会把该组当作普通用户下发。

当前更换/验收使用 [Owned US Exit Retirement](../../../.github/workflows/owned-us-retirement.yml)：preflight、apply（已应用后拒绝重复）、verify、status、cleanup。一致性备份在宿主 `/root/Xboard/backups/us-retirement-20261028/`，字段与绑定快照在容器 `storage/app/backups/us-retirement-20261028/`；回退先核对新订单和绑定，再仅恢复字段，不能整库覆盖。只有一个固定美国出口，故障时不能迁到另一个美国IP，香港备用保留。服务商自动续费未由本流程操作。

历史 Production Deploy 提供只读清单 `inspect-dedicated`、原链路基线 `baseline-owned-dedicated`、预览 `preview-owned-dedicated`、应用 `attach-owned-dedicated` 与验收 `verify-owned-dedicated`。预览和应用均核对运行镜像的完整提交号，但其接入命令的 1 倍率前提尚未适配当前 2× 池，不应作为本轮更新或重建入口；旧 baseline-owned-dedicated / verify-owned-dedicated 固定为历史十三出口范围，不再适用于当前池。当前验收复用服务器已有 sing-box，临时凭据文件在私有目录中使用并删除，只输出连通性、权限和订单状态。构建、生产应用和真实验收的状态分别记录于[进展记录](../../../progress-log.md#2026-10-19自建线路接入固定出口池)。

每个物理出口最多绑定 5 个有效订阅账号，后端保留唯一的出口/槽位和账号约束。下单预留名额 2 小时，取消或超时释放；已支付待开通的订单持续占位。流量耗尽不释放仍在有效期内的绑定。正常续费保留出口；到期后续费需重新取得可用名额。

套餐售罄时从新购列表隐藏，已订阅用户可通过原套餐详情续费。数据库事务锁串行分配同一套餐的名额，SQLite 与 MySQL 均适用。普通用户只能认证公共节点；购买用户只能认证公共节点及分配的出口。订阅过滤、REST 用户列表和 WebSocket 增量同步使用同一绑定规则，复制别人的节点地址也不会获得授权。

## 历史 SOCKS 出口的部署与上架

以下保留最初 1× SOCKS 出口的初始化步骤，仅用于理解旧实现；不是当前 2× 自建固定池的重建操作手册。使用 `dedicated:prepare` 新建 2× 出口前，必须先适配其硬编码倍率并完成独立验收，不能只修改模板文案。当前自建池的配置与权限应按上面的现行映射维护。

1. 备份 SQLite 数据库（在线 backup 并检查完整性）、`.env`、Compose、插件、主题和入口 Nginx 配置。
2. 发布镜像并通过现有生产更新流程执行迁移，核实容器 OCI revision。
3. 在服务器本地准备权限 0600 的 JSON 清单，字段为 `backend_template_id`、`frontend_template_id`、`port_start`、`exits`；每个出口包含 `ip`、`port`、`username`、`password`、`standby`。模板必须是同一条 VLESS WebSocket 入口的后端和公开节点。不得把私密清单上传仓库或输出日志。
4. 执行 `php artisan dedicated:prepare <私密清单>`，创建隐藏套餐和各出口的后端/前端节点。命令可重复执行，不重复创建或自动开放销售，也不覆盖已存在的价格、凭据或绑定。
5. 在入口 Nginx 为新节点的 WebSocket 路径配置回环转发，保留现有访问控制。先 `nginx -t` 再 reload；后端端口不向公网开放。
6. `php artisan dedicated:check` 校验后端心跳和经 SOCKS5 的真实 HTTPS 出口 IP；连续两次成功后标记健康。用专门测试账号逐条验证客户端 TLS → WebSocket → VLESS → 美国出口，核对流量入账和未授权账号拒绝；测试结束撤销账号。
7. 所有销售出口与备用出口验收通过后，再开启套餐 `show/sell`。生产新购只开放已验证容量，不能靠添加套餐卡片代替代理通路验证。核对普通用户套餐页面、月付金额和新购/续费流程，不进行真实付款。

### 入口首次开通修复

生产 `xboard-node` 基于上游 `0a29338e1f102a462363ce3527417029f89bab28`。此版本在零用户启动后，先检查旧用户列表能否启动内核，再应用新用户；因此首个用户购买后，专属端口仍不监听，入口返回 502。

`.docker/dedicated/node-idle-start.patch` 修复全量同步和增量新增两条路径：先准备新用户状态再启动内核，失败时还原用户和限速状态。使用 Go 1.26.2 执行 `bash .docker/dedicated/build-node.sh /绝对路径/xboard-node-linux-amd64`，生成 `0a29338-dedicated.1`，保持生产构建标签。脚本只构建，不修改线上服务。

部署前备份入口程序及配置，核对上传二进制哈希，再替换程序并重启 `xboard-node`。验收必须包含“空节点启动 → 新增首个用户 → 无重启建立代理连接”，同时检查原有公共节点；只重启旧程序会暂时掩盖问题。回退时恢复备份程序并重启。

## 健康和故障处理

调度器每分钟运行 `dedicated:check`。连续三次失败后停止分配该出口；连续两次恢复后重新纳入可用资源。健康信息超过 5 分钟未刷新也会停止分配。当前仅保留1个美国销售出口，没有另一个美国固定备用；香港公共备用仍可使用，原三销售两备用是历史SOCKS阶段配置。

后台检查或用户更新订阅时，在不超过每个出口 5 个账号的前提下迁移绑定；恢复后不主动迁回原 IP。新、旧节点同步撤销或增加账号，REST 轮询同步间隔以现有节点设置为准。备用容量不足时保留原绑定等待恢复，公共线路仍可使用，不挤占已满出口。

`php artisan dedicated:status` 显示健康与占用。迁移/预留/释放记录保存在 `v2_dedicated_assignment_log`，不含用户密码或代理凭据。排查故障应同时检查健康检查调度、节点心跳、Nginx 和真实代理请求，不能仅凭 443 端口可连接判定出口可用。

暂停新购时设置套餐 `sell=false`；已有用户授权继续按有效订阅执行。不要通过恢复整库来回退商品文案或配置，以免覆盖新增订单和用量。

### 普通套餐折抵换购修复（2026-10-13）

曾运行较新上游版本的数据库已执行 `2026_05_30_000000_rename_refund_amount_to_surplus_credit`，但本分支遗漏了对应代码，导致旧套餐折抵高于新套餐价格时向不存在的 `refund_amount` 列写入，创建订单返回 500。此故障发生在请求支付网关之前。

恢复上游 `34bb1fd` 的列重命名迁移及余额计算：统一使用 `surplus_credit` 保存退回站内余额的余款，历史已退回余额从下一次折抵基数中扣除。保留原迁移文件名，使已迁移数据库跳过重命名；旧数据库升级时保留列内金额。订单 API 额外提供 `refund_amount` 兼容现有主题展示，不再向数据库写入旧列。

执行 `vendor/bin/phpunit tests/Feature/Dedicated tests/Feature/Payments`，覆盖折抵超过/不足新套餐价格、零元结算及重复开通、取消预留、旧列金额迁移与已迁移数据库再次升级。生产核验使用事务回滚的下单请求，不替用户确认换购、不进行真实付款。
